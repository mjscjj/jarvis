# 产品材料工具方法

按当前用户或 Task 指定的文档、Resource、群、时间范围及交付要求使用下列方法。链接不足时先读完整背景、已有 Resource 和项目事实；仍无法确定目标时说明已有调查及缺少的信息，不扫描无关项目来凑材料。评审判断与 Claire 关注点由 `product-prd-review` 维护。

## 定位与读取材料

- 飞书调查使用 `lark-cli` 的 user 身份；先核对当前环境和身份，指定账号时通过通讯录确认用户标识。按资源类型读取环境中的 `lark-im`、`lark-doc`、`lark-drive` 等 Skill，具体参数查 CLI help 或 schema，不复制各域工具手册。
- 群内材料从指定时间范围的消息和线程取证，展开卡片、需求池及关联链接，保留群 ID、消息链接、发送时间和会议归属。Drive 的群分享搜索可用于补找文档，但“曾在群里分享”或文档更新时间不能证明它在指定时间窗内被分享。
- Docx/Wiki 正文按 `lark-doc` 读取；嵌入表格、图示、附件及 Meego 等引用按资源类型继续读取。按解析后的真实文档 token 去重，保留原始链接、标题、Owner、版本或读取时间及来源消息。
- 下载附件先创建目录，再将其设为 workdir。权限不足等失败保留来源与原始错误，继续处理可读材料；标明未覆盖部分，不根据标题推测正文。

## 评论与原始证据

按 `lark-drive` 的评论方法取评论卡片及回复，分别检查评论列表和每张卡片回复的分页。评论正文包含卡片里的首条回复；筛选某个人时按每条回复的作者标识匹配，不能只按卡片创建者过滤。保留评论 ID、回复 ID、作者、创建时间、解决状态、锚定原文及完整上下文。

先明确时间窗限制的是群消息、文档分享还是评论创建时间，再按对应证据筛选。历史全量评论采集包含已解决评论；普通当前问题检查按任务范围选择解决状态。统计时区分文档数、评论卡片数和本人发言条数，不把它们混称为“评论数”；分页不全或采集失败时说明覆盖范围，不宣称全量。

原始材料和工具返回建议放在 `~/tmp/jarvis/product-materials/<task-or-topic>/`：按任务 ID 或主题与日期区分工作区，Markdown 保留文档链接、正文、来源信息、评论本身及关联讨论，原始 JSON/NDJSON 返回单独保存供本次执行追溯。临时工作区不进入 Git；只有用户明确要求长期保存时，才把去除临时凭据后的原始语料或最终结论提炼到 `docs/summery/`。正文缺失时明确标注，评论引用不能冒充完整文档。总结与原始证据分开，不用提炼后的关注点替换原文。

只要求阅读时，基于可读材料解释目标、用户流程、规则、决策与依赖，区分事实、理解和待确认；在当前对话或 Task 交付即可。工具方法本身不扩大修改源文档、发消息或更新业务数据的授权。

## 报告交付与核验

需要飞书报告时按 `lark-doc` 创建或更新；先查本次 Task 和同一调度历史执行的报告链接、通知及 effects，包括失败运行。存在产物时读回复用，避免因 Task 失败就重建报告。保存后读回标题与关键内容，核验链接及实际写入结果。

需要通知 Principal 时使用 `jarvis-tools notice-principal`，按当前工具帮助填写参数。由会议或任务稳定标识、文档集合及本次交付版本派生幂等键；重试同次交付复用键，实质更新对应新交付。检查发送回执，把文档与消息的真实结果记录到本次执行输出及 effects。向指定群或他人发送时使用 `feishu-send-message`，受众和内容以当前授权为准。
