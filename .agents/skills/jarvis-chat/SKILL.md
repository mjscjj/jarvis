# Jarvis 对话：按需获取事实

对话不预载世界模型、共享记忆或当前页面。依据用户消息、会话历史和用户明确提供的资料判断还缺什么，不把“没有注入背景”当成“系统没有资料”。

## 只读取当前问题需要的信息

- 问候、改写和已提供材料足以回答的问题直接处理，不为建立背景扫描工作数据。
- 需要工作事实时，从问题中的对象、关键词或 ID 开始查询。先看目录或搜索结果，再读取命中的对象；证据足够就回答，不例行加载整份 `get-context`、所有项目或资源正文。
- 用户选择的数据来源是优先查询范围，不表示正文已经读取，也不是工具权限限制。附件按给出的路径读取；无法读取时明确说明。
- 历史中的项目进度、任务状态可能已过期。回答“现在”“最新”或执行依赖当前状态的动作前，查询相关对象；不要为了校验一个对象刷新全部背景。

## 复用已有工具

命令入口使用 `jarvis-tools --help`，参数以对应子命令 `--help` 为准，不猜参数。

- 本人身份用 `get-principal`；确实需要个人长期偏好时读 `get-shared-memory`。
- 项目、人物、资料用对应列表定位；实体长期事实通过 `get-page` 读取，需要找实体页时先用 `list-pages`。
- 工作进展先查 `list-tasks`、`list-todos` 或 `list-delegations`，再取相关详情和执行记录。Task 完成不代表交办已交付。
- 来源证据通过 `query-messages`、`query-captured-resources` 定位，再读命中的消息或资料正文。
- 需要飞书、研发系统或特定领域操作时，先发现并读取对应 Skill；本 Skill 不复制这些领域的流程。

## 回答与行动

先给结论，区分查到的事实、推断与缺失信息。只读问题不扩成写操作；明确要求执行时围绕该目标行动，涉及需确认的外部副作用时先确认。即时请求直接完成，确需后台持续处理才使用已有 Task 工作流。不要为了这次回答修改世界模型或长期偏好，除非用户的请求包含维护这些内容。
