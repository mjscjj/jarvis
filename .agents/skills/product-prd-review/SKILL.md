# 最近一次产品会议 PRD Review

先读取当前 Task 的完整指令、背景、同一 ScheduledTask 的历史 Task 与运行结果，确认目标群、关注的产品范围和本次交付要求。群名、群 ID、会议类型或产品关键词属于任务配置；不要把某个群或固定时间窗口写成通用规则。

## 定位最近一次会议

使用 lark-cli 的 user 身份读取目标群消息。若 Task 已给出明确会议消息、会议 ID 或需求清单，以它为锚点；否则从最新消息向前分页，结合会议通知、议程、会后材料、线程和卡片，找到最近一次符合产品范围的初评、组会或需求评审。确认该次会议后停止，不继续扫描更早会议，也不把固定七天当作读取范围。

锁定会议时记录可稳定识别它的信息，例如消息 ID、会议 ID、会议时间与标题。若最新消息只是在讨论旧会议，沿引用回到所属会议；无法区分两次会议时保留不确定性，不把它们合并成一批。

## 找齐本次 PRD

展开该会议对应的消息、线程、卡片和需求清单，收集直接分享或通过 Meego、One Pager、Wiki 等材料关联的 PRD。以飞书文档 token 或真实文件 ID 去重，保留每份文档的来源消息、需求名称和原始链接。只纳入属于本次会议的材料；历史背景文档只有在理解当前 PRD 必需时才作为引用读取，不单独算成本次 PRD。

读取飞书群消息时使用环境中的 lark-im 能力，读取 Docx/Wiki 时使用 lark-doc；需要从云空间找真实文档或解析 Wiki 时使用 lark-drive。使用 user 身份读取，权限不足时记录原始文档、来源和错误，不根据标题推测正文，也不因一份失败中断其他文档。

需要下载图片、画板或附件到临时目录时，先在当前已存在的工作目录中单独创建临时目录并确认成功，后续命令才可以把它设为工作目录；不要让命令在一个尚不存在的 `workdir` 中创建该目录。

## 阅读与 Review

对每份可读 PRD，读取 `product-doc-read` 和 `product-doc-review` Skills，并按当前文档的阶段、类型与复杂度调整调查深度。完整阅读正文、表格和影响理解的图示，必要时展开关键引用。

先还原产品要解决的问题、用户与主要流程，再检查真正影响交付的内容，例如流程和异常状态是否闭合、规则是否互相矛盾、指标能否衡量目标、跨端与数据依赖是否明确、验收和发布条件是否足够。不要强制套固定章节、凑问题数量，或把所有模板空白都判成缺陷。

每个确认问题应说明触发场景、原文依据、影响和可行建议；需要业务选择的内容单列为待决策。区分原文事实、Agent 判断和权限造成的未覆盖范围。

## 生成与交付

每份可读 PRD 创建一份独立飞书评审文档，标题能识别原 PRD 和本次会议。文档包含原 PRD 链接、读取版本或时间、产品理解、主要发现、待决策事项和未覆盖范围；具体结构与篇幅按材料调整。创建后读回标题和关键内容，确认链接有效。

本次包含多份 PRD 时，再创建一份批次汇总文档，列出会议、全部发现的 PRD、各评审报告、最需要关注的跨文档问题，以及因权限未读的材料。不能读取的 PRD 不创建空报告，但必须留在汇总里。

完成后使用 `jarvis-tools notice-principal` 由 Bot 通知 Principal，正文简要说明发现、完成和未读数量，给出批次汇总及各报告链接。使用由会议稳定标识和本次文档集合派生的幂等键；读回发送结果，并把飞书文档与消息作为 effects 写入本次执行结果。

## 重跑与停止

执行前检查同一 ScheduledTask 的历史结果，以及来源会议、报告标题、已有飞书文档和 Principal 通知等外部产物。Task 显示失败或没有结构化结果，不代表外部写入没有发生；运行中断后必须先读回已有产物，只补缺失步骤，不重复创建已存在的报告或重复通知。

若最近一次会议已经处理，比较已记录或读回的文档 token、版本或更新时间：

- 出现更近的会议时，处理新会议；
- 同一会议有新增 PRD 或正文发生实质变化时，只补充或更新受影响的报告，并更新批次汇总；
- 同一会议及材料均无变化时，记录“无更新”后结束，不重复创建文档或发送通知。

源 PRD 保持只读。报告创建、Principal 通知和运行记录是本 Skill 的交付；不要顺带修改产品需求、OKR、Meego 工单或群消息。
