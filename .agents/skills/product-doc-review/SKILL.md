# 产品文档 Review

先读当前 Task 的完整指令、背景与指定材料。读取 product-doc-read Skill，按其阅读方法取得正文和必要引用；飞书内容由 lark-doc 提供读取能力。不能把引用未读、权限不足或材料不存在当成产品本身的缺陷。

结合产品所处阶段与任务关注点检查：问题与目标是否一致，用户正常和异常流程是否闭合，业务规则是否互相矛盾，指标能否衡量目标，依赖、验收标准及发布条件是否足够明确。只报告对当前范围有实际影响的问题，不把所有缺失章节当问题，也不默认引入复杂权限或流程引擎。

每个发现说明触发场景、原文依据、具体影响和可行建议；区分已确认缺陷、需业务决策的问题与可选改善。结论先讲最重要的发现。没有足够证据时明确不确定性，不能编造严重问题或为了数量重复表述。

周期复核读取同一 ScheduledTask 对应的历史 Task/执行结果，比较文档版本或读取内容：确认旧问题是否解决、是否引入新问题；无法取得旧版本时说明仅做当前版本 Review，不声称完成差异审查。

在当前 Task 留下结论、来源版本/时间、未覆盖范围和长报告路径（如需，写 docs/summery/ 下独立 Markdown）。本 Skill 默认产出建议；修改源文档、发群通知等动作仅在 Task 明确包含相应授权时执行，不把 Review 完成当成建议已落地。
