# 我的交办：Task 只做本次核验

下述核验规则只适用于原始线索 action_type=delegated_followup 或冻结来源带 delegation_id 的检查
Task。其它 Task 保持自身目标，只在发现独立交办时使用末尾的回灌规则。

交办的主体是 M3 产出的 Todo，交办进展独立于 Todo/Task 的执行状态。本 Task 的目标是
完成一次有证据的检查，不是替对方交付，也不是无限看护到对方做完。

## 找到同一条待办

默认 Task 上下文只展示触发原话和简报，未必展开分类与关联。对来源为 Todo 的 Task，
先读取 get-task 的 source 与 annotation 冻结片段，确认是否属于交办核验，不从原话里的
“让某人完成”直接推成自己负责交付。手工检查的 source 通常已包含 delegation_id。

首次 delegated_followup Task 使用 task.todo_id；后续检查从冻结包的
annotation.delegation_id 或 source.delegation_id 读取交办 ID。先用 get-delegation
读取原始来源和当前进展，再用 list-delegation-tasks 查看已有核验记录，避免重复动作。

source_payload 保存最初交办的完整来源、会话、参与人、资源及 M3 理解；它回答当时
为什么交办。content 是可更新的核验结论。原始来源中的负责人和期限可能已过期，
必须结合新证据判断，不能改写冻结背景，也不能把当前摘要当成原始事实。

## 核验与回写

围绕真实交付物按需查询原线程、文档、MR 或工单。记录确认的事实、证据来源、当前
负责人和事项、期限变化、不确定性，以及有依据的下一检查时机。用 update-delegation
把完整当前理解写入宽松 content；推荐用 summary 写给人看的当前进展，其余结构自由。
带上刚读取的 expected_version；并发冲突时重新读回再判断，不能覆盖别人的新证据。

- 查证完成但对方尚未交付：待办保持未结束，写回后本 Task 返回 completed。
- 有可靠交付证据：写清依据并设置 closed=true；Task 仍只表示这次核验完成。
- 明确取消、误判或被另一条待办替代：在 content 写清原因和关联，再结束待办。
- 查不到：如实记录检查范围与未知，不能把“没看到”当成“没做”；按本次检查是否完成
  判断 Task 的结果，不将未知推成对方已交付或交办失败。

只有本次检查本身尚待材料生成等条件时才使用 waiting；不能单因为“对方还没做”就
让 Task 一直 waiting。旧版持续跟踪 Task 恢复时也按本轮检查收口，后续复查由主动巡视
按交办进展决定。检查失败、被中断或 Task done 都不自动改变待办闭环状态。

首次检查不重复通知负责人。检查发现需要催办、改派或升级时，把建议和依据写入进展，
不把只读核验自动扩大成对外行动；用户明确要求的对外动作另按普通 Task 与统一审批策略执行。

## 在其它 M5 工作中新发现交办

处理会议、消息或文档时发现新的独立交办，用 append-clue 回灌完整证据，让 M3 识别并
产出 Todo；不要在 M5 另建交办主体。每个独立交付物使用稳定 external_id，携带来源 Task、
会议/文档标识、逐字行动项和理解所需背景。已有同一待办的新证据应引用其 ID，保留原文。
