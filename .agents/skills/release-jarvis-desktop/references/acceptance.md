## 必须区分的证据

- 源码单测通过：仅证明所测逻辑，不证明实际包包含该修复。
- validate-runtime、codesign、hdiutil 通过：证明对应包检查，不证明用户引导和跨版本升级。
- 模拟 API/Tauri IPC 的浏览器测试：证明页面交互，不证明下载、验签、替换 App 或 WKWebView 缓存行为。
- 真实安装升级：记录具体旧版、候选摘要、测试状态目录、服务和界面结果。
- 当前开发者账号可用：不能证明新用户首次授权完整。

## 最小发布验收

正式发布至少检查封存产物、新安装和已发布版本升级。使用独立 macOS 测试用户或专用测试机，保留该场景自己的状态；不要把当前真实用户数据当可删除夹具。普通源码临时目录测试不能自动冒充真实 Tauri 用户目录隔离。

新安装：从候选 DMG 安装，进入引导，保存设置，重启后保留；确认包内 CLI 被实际使用。缺少授权条件时明确记录。未经请求不发真实测试消息。

升级：从明确旧版开始，使用候选签名更新包走真实 updater，确认新版本、业务 Web 可加载、配置/数据保留。仅拖拽新 DMG 覆盖不能代替 updater 验签和替换验收。

根据变更选择专项场景：

| 变更影响 | 应覆盖 |
| --- | --- |
| 基线/覆盖配置、onboarding | 改过基线、runtime 旧未知键、类型错误、保存后重启；用户参数不丢。 |
| 资源同步 | manifest 缺失、有用户定制、历史已重建错误 manifest、备份失败和同步中断。确认哪些状态自动修复，哪些必须显式恢复。 |
| Web 缓存/桌面入口 | 保留旧 WebView 缓存后升级，入口与 chunk 加载，真实界面可操作。 |
| app-service/恢复 | 启动错误、进程退出、页面加载失败，实际可用的诊断/重试/更新入口。未实现的恢复能力不得写通过。 |
| 采集策略 | 关闭期间消息不采；重新开启后首次发现会话也遵守边界。 |
| waiting/续跑 | 旧执行清理完成后才继续；重启不重复激活。 |
| Lark/CC Connect/授权 | 新用户授权、当前连接、变更涉及的消息/文档/事件链路，按真实授权范围验证。 |

场景通过以用户可见结果和对应持久状态为准。发行说明不能声称修复没有验证的历史状态。

## 失败处理

错误要带阶段、文件/组件、原始诊断和下一步；不要统一归为“打包失败”。真实旧库需要额外迁移、用户配置恢复或默认资源重置时，先明确涉及范围，不临时增加猜测兼容，也不删库让测试变绿。

如果必需场景无法执行，候选可交付为“待验收”，不可自动提升为正式发布。若用户明确决定接受某项限制，记录具体限制和决定，不篡改测试结果。
