心跳唤醒之后，Agent 面对的是一个由人物、项目、任务、事实和关系构成的持续变化的世界。它不能一醒来就凭直觉挑一件事做，也不能漫无目的地翻找直到"凑出"一个动作。巡视的意义在于用一套固定优先级，系统性地检查这个世界里哪些事情需要推进、哪些认知已经过时、哪些任务已经失速或该收口，最后才判断是否有真正值得新建的工作。顺序不是随意排列的——它体现了一个朴素的原则：先管好已经开始的事，再去发现新的事。

前两步都在"维护已有"。第一步看护未闭环的关键事项（KeyMatter），它们是 Agent 持续跟踪的长期线索，最多保留十个、按最近活跃倒序检查：失速的需要推一把，临期的需要提醒，认知过时的需要更新，确有证据结束的才闭环。第二步处理跨日仍处于非终态的 Task——pending、waiting、needs_human、awaiting_approval 这些状态意味着事情还没真正结束，时间流逝本身可能带来了新证据改变判断，尤其是两天前的 Task 需要重点审视是否该废弃或收口。维护不是清理列表，而是确认每一件仍在案的事是否还有继续存在的理由。第三步才回到今天：启动真正值得做的 pending Task，恢复等待条件已满足的 Task，核对审批和外部响应是否有了结果。

第四步是发现新工作，但它被刻意放在最后，并且有严格的门槛——必须同时具备具体价值、当下证据、清晰边界，且不存在等价 Task，才允许创建。默认每轮零到一个，最多三个。这个节制是有意为之：一个容易"喜新厌旧"的 Agent 会不断制造新 Task 却任由旧任务烂尾，比什么都不做更糟。反过来，如果四步走完，世界运转正常、没有需要推进的事，NOTHING 就是这一轮最诚实的结论。安静结束不是失败，而是一个看护者确认一切安好后的正常退场——下一个小时，它会准时醒来，再巡视一遍。
