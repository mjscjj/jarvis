# Jarvis 前端体验重构计划

> Status: implementing
> Started: 2026-08-05
> Scope: `web/`，必要时补最小 API 投影；不改变 M2 → M3 → M5 核心语义。

## 目标

把当前按后端实体平铺的管理后台，重构成面向 principal 的主动式任务控制面。用户进入页面后应能立即回答四个问题：

1. 现在有什么需要我决定或补充？
2. Jarvis 正在推进什么、为什么等待？
3. 今天实际完成了什么、产生了什么结果？
4. 系统如何理解我的项目、人物和工作背景？

## 信息架构

主导航只保留高频用户意图：

- **今日**：需要我处理、正在推进、今日结果、用户影响风险。
- **工作台**：需要我、进行中、等待中、已完成、异常。
- **回顾**：个人总结、群总结、趋势、产出。
- **记忆**：项目、人物、会话、资源、我的资料。

低频入口收进管理菜单：

- 线索
- 自动化
- 系统设置
- 运行状态

## 实施阶段

### Phase 1：框架

- Hash 路由和可恢复页面地址。
- 中文分组导航，展开宽度 184px，折叠宽度 64px。
- 移除无效全局刷新，刷新归属具体页面。
- Jarvis 对话改为覆盖式面板，不再压缩主内容。

### Phase 2：核心工作流

- 今日首页直接展示具体行动项，不只展示数字。
- 工作台统一 Task 状态心智模型。
- 首页“需要我”的数量和点击后集合严格一致。
- Task 详情先展示决定、动作、对象和外部副作用。
- 原始提示词、JSON、Session 等统一降级到开发者信息。
- 执行过程与详情保持同层，不叠加第二个大 Modal。

### Phase 3：次级页面

- Todo 改称线索，默认降低历史终态噪声。
- 用户自动化与系统等待唤醒分开展示。
- Progress 改称回顾，减少三层 Tab。
- Background 改称记忆，浏览优先；我的资料成为次级入口。
- Debug 和配置统一进入管理区。

### Phase 4：视觉和验收

- 统一中文术语、状态色、空状态、加载态和主要操作。
- 1280×720 与 1440×900 核心流程无横向滚动。
- 页面、筛选和 Task 详情支持刷新与前进后退恢复。
- 从今日首页进入并完成一次审批不超过两个主要跳转。
- 主页面不展示原始错误栈、logid、M3/M5 等开发信息。
- 完成 typecheck、前端测试、生产构建和真实浏览器验收。

## 代码边界

- `App.tsx` / `pageContext.tsx`：导航、路由、全局布局。
- `Overview.tsx`：今日首页。
- `Tasks.tsx` / `tasks/`：工作台与 Task 详情。
- `Todos.tsx` / `ScheduledTasks.tsx`：线索与自动化。
- `Progress.tsx` / `Background.tsx`：回顾与记忆。
- `Chat.tsx`：上下文对话。
- `styles.css` / `styles/*.css`：共享布局和页面局部样式。

每个阶段独立检查、独立提交；共享文件只由主 agent 集成。
