## 0. 一页纸速览

**一句话**：不是「有任务/消息进来才 think→act」的被动循环，而是「以**目标**为北极星，**周期性醒来**重新审视全局，像人一样自主决定此刻最该做什么（含"什么都不做"）」的主动决策引擎。

```
五实体（世界模型）            六模块（决策循环，每 tick 一轮）
┌─────────────────┐          ┌──────────────────────────────────────┐
│ Principal 决策主体│          │ ① 感知 Perception  多模态信号→统一Observation│
│ Goal      目标★  │          │ ② 状态/记忆 State   组装决策上下文(三层记忆) │
│ Person    关键人 │  ───►    │ ③ 候选生成 Propose  N个候选(含忽略/等待/补背景)│
│ Resource  资源   │          │ ④ 评估 Score       贡献度×可行性×成本/风险  │
│ Signal    触发源 │          │ ⑤ 选择 Select      选top或忽略+硬护栏        │
└─────────────────┘          │ ⑥ 执行/建议 Act    →抽象能力接口→任意后端    │
                             │ ⑦ 观察回写 Observe  结果→更新目标/记忆/校准  │
                             └──────────────────────────────────────┘
                             横切护栏：反空转 · 自激励检测 · 预算闸 · 自主度分级
```

**三条红线**：① 忽略/等待是平等候选；② 防自嗨（反空转 + 自激励隔离）；③ 反馈闭环（决策→行动→观察→回写）。

**四个已定设计选择**（本文前提，非待议）：
1. **目标驱动 + 周期心跳**，不是纯事件驱动。
2. **显式目标树为权威**，引擎可从信号建议新目标/子目标，但**必须经确认才进树，不自动漂移**。
3. **决策走「候选生成→打分→选择」三段式**，可解释、可复现、可审计（对齐 survey §5.3「外部信号 > 纯内省」）。
4. **行动 = 抽象能力接口（Capability）**，决策引擎执行无关：codex、发消息、调 API、乃至"交给人做"都是能力的一种实现。

## 1. 与 ReAct 的本质区别（为什么要另起一套）

ReAct（`survey §1.1`，`Thought→Action→Observation` 循环）是几乎所有生产 agent 的内核，但它的隐含假设是**被动**的：有一个任务/prompt 进来，agent 才开始想、做、观察，直到产出 Final Answer 就结束。这与"人如何决定下一步做什么"有几处根本不同：

| 维度 | ReAct（被动） | 本系统（主动、类人） |
|---|---|---|
| **谁驱动循环** | 任务/prompt 触发；无任务则不动 | **目标 + 周期心跳**；即使没有新输入也会醒来审视全局 |
| **上下文形态** | system prompt + 对话消息（非结构化文本） | **实体化的世界模型**（主体/目标/人/资源/信号）+ 分层记忆 |
| **"下一步"从哪来** | LLM 在链内直接想下一个 action | **显式候选生成→打分→选择**，从一组候选里择优 |
| **"什么都不做"** | 无此概念（必须持续 act 到 Final） | **忽略/等待是一等候选**，且常常是最优解 |
| **终止** | 产出 Final Answer 即结束 | **不终止**，是常驻的决策主体，目标达成/搁置只是状态变化 |
| **执行耦合** | 工具调用内联在推理里 | **决策与执行解耦**，通过抽象能力接口下发 |
| **学习** | 单轮内反思（Reflexion 等），跨轮不积累 | **反馈闭环**：结果回写目标进展/困难，跨轮越来越准 |

> 关键点不是"ReAct 不好"——恰恰相反，**单个候选行动的执行内部完全可以是一次 ReAct 循环**（见 §3.6）。本系统是在 ReAct 之上加了一层「像人一样、以目标为中心、主动决定该不该做以及先做哪件」的**决策/调度外壳**。可以理解为：ReAct 回答"怎么把这件事做出来"，本系统回答"此刻到底该做哪件事、值不值得做"。

### 1.1 "像人"到底像在哪（三个可检验的特征）

避免"像人"沦为口号，本文把它落成三个**可检验**的特征：

1. **主动性**：无外部输入时仍会决策（哪怕决策结果是"继续等待"）。检验：给系统一个空的信号队列，它仍能基于目标产出合理的下一步或明确的"暂无值得做的事"。
2. **取舍性**：面对多目标/多候选，会按"贡献度×可行性×成本/风险"权衡，而非来一件做一件。检验：构造两个候选（高贡献高风险 vs 低贡献低风险），系统的选择与配置的权衡口径一致且可解释。
3. **积累性**：做完会更新对世界的认知，下次更聪明。检验：同一目标第二次决策时，能利用上一次的结果（进展/困难/失败教训），不从零开始。

## 2. 世界模型：五个一等实体

决策的前提是有一个**结构化的世界模型**（而非把一切塞进 prompt）。五个实体：

### 2.1 Principal（决策主体）
- **是什么**：这个引擎"替谁做决策"。谁、角色、画像、**偏好**（沟通风格、风险偏好、什么事必须问我）、**约束**（时间、精力、不可碰的红线）。
- **为什么一等**：同一个候选行动，对不同主体的价值/风险不同（例：激进 vs 保守的人对"自动发消息"容忍度不同）。主体画像是打分的调制器。
- **数量**：通常一个（单主体）；多主体属扩展，不在 MVP 概念内。

### 2.2 Goal（目标）★ 新增、最关键
- **是什么**：引擎的**北极星**。一棵树：`目标 → 子目标 → 当前重点`。每个节点带：`状态`（活跃/搁置/达成/放弃）、`进展`、`困难/阻塞`、`deadline`、`优先级/权重`。
- **为什么一等**：你的第一决策维度就是「对目标的贡献度」——**没有显式目标，贡献度无从算起**。原始构想把"目标"混在"关键事情（目标/进度/困难）"里，本文将其独立为一等实体。
- **权威与漂移控制**：**目标树以显式维护为权威**。引擎可以从信号（如老板交办、反复出现的诉求）**建议**新目标/子目标，但建议进入一个"待确认"区，**经确认才并入目标树**。引擎自身不得静默改写目标（防"目标漂移"导致决策不可复现——这与 `survey §5.3` 反对"纯内省不可靠"同源：目标若能被模型随手改写，等于让不可信推理决定北极星）。
- **与"待办"的区分**：目标是"想达成的状态"；为达成目标要做的具体动作是**决策模块的产物**（候选行动 / 已选行动），**不是**输入实体。不要把 to-do 列表当成目标。

### 2.3 Person（关键人）
- **是什么**：与主体/目标相关的人：老板、同事、朋友、其他关键人、其他人。带`关系`、`角色权重`（如老板权重最高）、`沟通偏好`。
- **为什么一等**：信号的价值和紧急度强依赖"谁发的"（老板的一句话 vs 群里闲聊）；行动的对象也常是人（通知谁、约谁）。
- 角色可粗分：`leader / key / peer / friend / other`，权重可配置。

### 2.4 Resource（资源）
- **是什么**：决策/行动可利用的东西，两类：
  - **信息资源**：文档、会议纪要、历史结论、外部知识。
  - **能力/工具资源**：引擎能调用的 Capability 清单（见 §3.6）——本质是"我能做什么"的自我认知。
- **为什么一等**：**可行性**打分直接取决于"完成这个候选，需要的信息/工具是否具备"。资源清单是可行性判断的依据。

### 2.5 Signal（触发源）
- **是什么**：一切可能触发或影响决策的输入：消息、图片、声音、邮件、定时器、webhook、系统事件……
- **关键设计——归一化**：决策模块**不应关心信号的模态**，只关心"它对世界意味着什么"。因此原始信号先经**感知层**（§3.1）归一化成统一的 `Observation`，再进入决策。
- **为什么一等**：它是"世界发生了变化"的载体；但注意——**在目标驱动模型里，信号只是唤醒/更新状态的诸多来源之一，不是决策的唯一触发**（没有新信号，心跳照样决策）。

### 2.6 实体关系（概念图）

```
              服务 / 贡献
   Signal ──观察──► [世界状态更新] ──► Goal(目标树) ◄── 主体的意图
     │                                   ▲
     │ 关于                              │ 关于/由谁推进
     ▼                                   │
   Person ◄──关系──► Principal(决策主体) ─┘
                        │ 可利用
                        ▼
                     Resource(信息+能力)
```

> 五实体共同构成每次决策的"输入世界"。它们的**当前快照**属"实体状态层"，它们的**历史变迁**属"情景记忆层"（见 §3.2）。

## 3. 决策循环：六个模块（每 tick 一轮）

一次心跳（tick）从感知走到回写，是引擎的基本工作单元。整体流水：

```
   [心跳/信号唤醒]
        │
   ①感知 ─► ②状态&记忆 ─► ③候选生成 ─► ④评估 ─► ⑤选择 ─► ⑥执行/建议 ─► ⑦观察回写
        │                                                                    │
        └────────────────── 回写更新世界状态，供下一 tick ◄───────────────────┘
```

### 3.1 ① 感知层 Perception（多模态 → 统一观察）
- **职责**：把任意模态的原始 Signal 归一化成统一的 `Observation`。
- **Observation 概念结构**：`{来源(谁/哪个渠道), 时间, 语义摘要, 关联(指向哪个 Goal/Person/Resource), 紧急度, 原始引用}`。
- **为什么单列**：这是**通用性的关键**。新增一种触发源（如接入语音）= 新增一个感知适配器，**决策模块零改动**。多模态理解（图片 OCR、语音转写）都封装在这一层。
- **fail-fast**：无法归一化的信号（解析失败）应**显式暴露**为一条"无法理解的观察"，而不是静默丢弃或臆测其含义。

### 3.2 ② 状态 & 记忆 State & Memory（三层，别一锅烩）
原始构想说"所有实体数据、历史数据、历史决策都组织存储检索"。方向对，但"所有"混在一起会导致检索不出重点、context 塞爆模型。仿照人类记忆**分三层**：

| 层 | 内容 | 类比人类 | 特点 | 每 tick |
|---|---|---|---|---|
| **工作记忆** | 本 tick 关注的极少量状态：活跃目标、刚来的观察、正在进行的行动 | 此刻脑子里想的 | 小、快 | **重建** |
| **实体状态** | 五实体的**当前快照**（结构化、权威、可查询更新） | 你对世界的认知 | 中、稳定 | 按需读取/更新 |
| **情景记忆** | 历史事件、**历史决策 + 结果反馈**、教训 | 你的经历 | 大、可检索 | 按需检索 |

- **组装决策上下文**：`工作记忆 + 相关实体快照 + 按需检索的情景记忆` → 拼成本轮决策的输入。**不是把全部历史怼进去**，而是按当前活跃目标/观察做相关性检索。
- **"历史决策+结果"这层最关键**：它是 §3.7 反馈闭环与打分校准的数据基础。没有它，引擎每次从零决策、不积累（就不"像人"）。
- 检索机制（向量/关键词/图）属实现细节，本文不定；概念上要求"能按相关性召回，而非全量注入"。

### 3.3 ③ 候选生成 Propose（发散：这轮我能做什么）
- **职责**：基于组装好的决策上下文，生成 **N 个候选行动**。每个候选标注：**服务哪个目标 / 做什么(what) / 怎么做(how) / 需要哪些资源**。
- **必须包含"元行动"**（否则退化成"必须干点啥"的空转机器）：
  - `忽略`：判定某观察不值得响应。
  - `等待/什么都不做`：当前没有正收益行动，保持观望。
  - `补背景`：去完善某个实体状态（如"这个目标信息不全，先搞清楚现状"）。
  - `追问/澄清`：向主体或关键人索取缺失信息。
- **对应 survey**：候选生成 = 在多个可能行动上**有意识地铺开**，是 `survey §1.1` ToT/搜索式拓扑在"行动空间"的应用（相对 ReAct 每步只想一个 action，更接近人"先想几个选项再挑"）。`survey §1.5` 亦指出"先列多个候选再报置信"能抑制过度自信。

### 3.4 ④ 评估 Score（你原始构想的三维度）
对每个候选，沿你提出的维度打分：

| 维度 | 含义 | 主要依据 | 备注 |
|---|---|---|---|
| **贡献度** | 对（所服务）目标的推进价值 | 目标权重 × 该行动对目标的边际推进 | 你的第一维度；依赖 §2.2 显式目标 |
| **可行性** | 现在能不能做成 | 所需信息/工具是否具备（查 Resource）、前置是否就绪 | 缺信息→低可行→倾向"补背景/追问"候选 |
| **成本/风险** | 代价与出错的负面后果 | 时间/调用成本 + **不可逆性 + blast radius** | **风险维度对齐 survey §4.1：按后果分级** |

- **打分信号的可靠性**（**直接采纳 survey §5.3 的硬结论**）：
  - 优先用**可外部验证的结构化信号**（目标权重、资源是否齐备、动作不可逆性、发起人角色权重）主导打分。
  - LLM 自报的主观置信度视为**待校准的弱信号**，权重压低（`survey §1.5`：RLHF 系统性过度自信，90%≈75%）。
  - 有条件时用**外部反馈/历史结果**锚定（§3.7 闭环 → §3.2 情景记忆）。
- **风险是第一闸门**（`survey §5.2`）：`错了多严重` 优先于 `多有把握`。高风险/不可逆候选，无论贡献度多高，都不能直接自执行（见 §3.5 与 §4 自主度分级）。

### 3.5 ⑤ 选择 Select（收敛：这轮做哪个）
- **职责**：从打分后的候选里选出本轮行动，或选择"忽略/等待"。
- **选择 = 打分排序 + 硬护栏叠加**（不是纯按分取 max）：
  1. 先按综合效用排序（贡献度、可行性、成本/风险的加权，权重可配置、体现主体偏好）。
  2. 叠加**硬护栏**（`survey §5.4`）：高风险/不可逆动作强制走"仅建议/待人工确认"路径；预算超限则降级；自主度分级决定"自执行 vs 只建议"（§4）。
  3. **若无正收益候选 → 选"等待"**，并可触发反空转降频（§4）。
- **可解释**：选择结果必须带**理由**（选了什么、为什么、淘汰了哪些、依据哪些因子），写入情景记忆与审计（`survey §4.5`）。这是"可复现、可审计"的落点。

### 3.6 ⑥ 执行/建议 Act（抽象能力接口 Capability）
- **核心抽象**：决策引擎**只产出"决策/意图"**，通过统一的 **Capability 接口**交给外部后端执行。引擎不关心能力内部怎么实现。
- **Capability 概念**：`{name, 输入契约, 前置/权限要求, 风险等级, 是否可逆}` + 一个 `execute(intent) → result` 的实现。典型实现：
  - 编码类：交给 codex / 其它 coding agent（**其内部通常就是一次 ReAct 循环**）。
  - 沟通类：发消息、发邮件、发通知。
  - 查询类：检索代码/网络/文档。
  - **人工类**：`交给人做`——把"建议"作为一种能力，产出给人的结构化建议，不自动执行。
- **建议 vs 执行**：由**自主度分级**决定（§4）。同一套决策，低风险可自执行，高风险只产出建议（human-in-the-loop）。这让"只给建议"和"自动做"统一在一个模型里，而不是两套系统。
- **对应 survey**：能力的风险等级 + 是否可逆，正是 `survey §4.1` 四级动作 tier 的输入；"授权/能否执行"应在**能力层/配置层做完全仲裁**，不由决策 LLM 在 prompt 里协商（`survey §5.4` 红线）。

### 3.7 ⑦ 观察回写 Observe & Learn（闭环，"像人"的最后一环）
- **职责**：行动执行后，观察结果，**回写世界状态**：
  - 更新 **Goal**：进展 +/−、困难消解或新增、状态迁移（可能达成/搁置）。
  - 更新 **Resource/Person**：新获得的信息、新发现的能力边界。
  - 沉淀 **情景记忆**：这次"决策→行动→结果"作为一条经历存档（成功/失败/教训）。
  - **校准打分**：用真实结果回校"贡献度/可行性"的估计（哪些行动真的推进了目标、哪些是空转）。样本不足时**不启用校准、保持保守**（`survey §4.3`）。
- **为什么不可省**：没有这一环，引擎每 tick 从零决策、不积累经验，只是"无状态的 ReAct 外壳"，谈不上"像人"。有了它，§3.4 的打分才会随时间变准。

### 3.8 一次 tick 的完整示例（走查）

```
[定时器唤醒 tick，无新信号]
①感知：信号队列空 → 无新 Observation（但主动性要求：继续决策）
②状态：活跃目标=[发布v2(重点,权重高), 帮朋友搬家(低优先)]；
        读实体状态发现"发布v2"当前困难="缺集成测试"
③候选：C1 让编码能力补集成测试   (服务v2, 贡献高, 可行[代码在手], 风险低[只读决策+可回滚])
        C2 追问同事测试环境细节    (服务v2, 贡献中, 可行, 风险低)
        C3 忽略/等待              (基线元行动)
        C4 补"搬家"目标的背景      (服务低优先目标, 贡献低)
④评估：C1 综合效用最高（高贡献 × 高可行 × 低风险）
⑤选择：选 C1；查能力"改代码"风险等级=中/可逆→按自主度规则(§4)：
        决策阶段只读、改动可回滚 → 允许自执行（否则产出建议待确认）
⑥执行：通过 Capability 把 C1 意图交给编码后端（其内部跑一次 ReAct）
⑦观察：结果=测试补齐并通过 → 回写"v2 进展+1、困难'缺集成测试'消解"
        → 情景记忆存一条成功经历 → 校准："补测试"对"发布"确有推进
[tick 结束，等待下一次心跳或高优先信号打断]
```

## 4. 横切护栏与三条红线（防自主 agent 的经典失败）

主动、目标驱动的引擎，最大风险不是"不会做事"，而是"**给自己找事做 / 自嗨 / 越权**"。四个横切护栏，其中三条是**红线**（不可退让）。

### 4.1 红线一：忽略/等待是平等候选
"什么都不做"必须与其它候选**同台打分**，而不是特殊分支。人也会判断"这事不值得现在做"。工程含义：候选池永远包含 `忽略/等待` 基线；当所有实质候选的综合效用都不为正（或低于阈值）时，选"等待"是**正确决策**，不是失败。

### 4.2 红线二：防自嗨（反空转 + 自激励隔离）
- **反空转闸门**：连续 N 个 tick 无正收益行动 → **降频休眠**（拉长心跳间隔），而不是硬凑动作。有高优先信号再唤醒回正常频率。
- **自激励隔离**：引擎自己产生的中间产物（如"我记下了一个想法"、内部笔记）**不得**在下轮被感知层当成外部新信号，再触发对自己的响应——否则会自我增殖出无穷任务。实现上：内部产物打标隔离，感知层过滤自产信号。（对应 Jarvis M3 `docs/modules/03-task-extract.md §6.3` 的"防自激励循环"，同一问题的通用化。）
- **tentative 不当真**：软想法/试探性念头，在没有升级为确认目标前，不驱动高成本/不可逆行动。

### 4.3 红线三：反馈闭环必须存在
§3.7 不是可选项。任何"决策→行动"后都要有"观察→回写"，否则退化为无状态 ReAct 外壳。**没有闭环的实现不符合本设计。**

### 4.4 护栏四：自主度分级 + 预算闸（对齐 survey，非红线但强烈建议）
- **自主度分级**（`survey §4.1` 四级 tier + §3.2 编码 agent 二维旋钮）：按动作的**不可逆性 + blast radius** 决定"自执行 / 记录后执行 / 暂存待人工 / 强制人工确认"。**高风险不可逆动作强制人工，无论置信度多高**。
- **两个正交旋钮**（`survey §5.4`）：能力边界（技术上能造成多大破坏，如只读 vs 可写）× 审批策略（何时停下问人）——分开配置。
- **预算闸**：每轮/每天的行动次数、LLM 调用、对外触达设上限；超限降级为"只建议"或"等待"，绝不无限自执行。
- **fail-closed**（`survey §5.4`）：打分/选择/能力调用失败、超时、歧义 → 默认转"建议/人工"，绝不放行。

> 护栏的**授权判定在配置/能力层做完全仲裁**，不由决策 LLM 在 prompt 里协商（`survey §4.2` / §5.4 最硬红线：一次 prompt injection 就能把"自己劝得不问人"）。信号/记忆里的任何不可信内容都属**数据平面**，不能改写"谁能做什么"的**控制平面**。

## 5. 在 survey 坐标系里的定位（本设计 = 三条轴的哪种组合）

`agent-decision-survey.md §0` 指出所有"agent 决策"都是三条正交轴的组合。本系统的定位：

| 轴 | survey 的谱系 | 本系统的选择 | 说明 |
|---|---|---|---|
| **轴A 推理拓扑** | 单链→ReAct→树/图→搜索 | **行动空间上的浅搜索**（候选生成→打分→选择）+ 单候选执行内部可 ReAct | 不在"推理"上做深树搜索，而在"行动选择"上铺开候选；深推理留给被选中的能力内部 |
| **轴B 反馈信号** | 内省 ↔ 外部硬信号 ↔ 人 | **外部结构化信号主导 + 人在高风险处兜底 + 结果闭环校准** | 直接采纳 survey 最硬结论：外部 > 内省；LLM 自报置信度降级为弱信号 |
| **轴C 决策主体** | 单agent→多agent→人机协同 | **单决策引擎内循环 + 关键处升级给人**（自主度分级） | 不上多 agent 辩论（对"做哪件事"这类判断非必要，见 §7 明确不做） |

**控制/数据平面分离**（survey 贯穿线）：本设计通过"感知层归一化 + 能力层完全仲裁 + 目标不被引擎静默改写"三点落地——不可信输入无法越过控制平面。

**与 ReAct 的关系再明确一次**：本系统不是 ReAct 的替代品，而是其**上位调度层**。ReAct 管"把选定的一件事做出来"，本系统管"以目标为中心、主动决定该做哪件事、值不值得做、要不要问人"。

## 6. 与"上下文/背景信息"改造的关系（回应原始构想第 1 点）

原始构想说"传统 ReAct 就是系统提示词+用户消息，我们改变这个模式"。本设计的回应：

- **背景不再是 prompt 文本，而是结构化世界模型**（§2 五实体）。system prompt 退化为"引擎的行为准则/决策原则"，**具体背景数据从实体状态层按需注入**。
- 每次决策的上下文 = `工作记忆 + 相关实体快照 + 检索到的情景记忆`（§3.2），**动态组装、按相关性裁剪**，而非把一大坨背景常驻 prompt。
- 好处：① 背景可结构化查询/更新（不像纯文本）；② 避免 context 膨胀；③ 背景与推理解耦，同一世界模型可服务多种决策原则。

## 7. 明确"不做"的（避免过度设计，写清楚反而防止未来乱加）

对齐 `survey §6.2 P3` 的克制精神：

1. **多 agent 辩论 / MoA / 深树搜索决策**：这些提升的是"难推理题"的质量。"此刻该做哪件事、值不值得"是**结合背景的价值判断**，不是数学难题，单引擎候选打分 + 人工兜底已足够。除非验证发现单引擎选择质量明显不足，否则不做。
2. **带数学保证的选择性升级（1−α 保证，Cascaded Selective Evaluation）**：优雅但需校准集与统计检验框架；通用/早期阶段样本稀疏喂不起。用保守阈值 + 人工兜底替代。
3. **重型防注入架构（CaMeL / Dual-LLM DSL 沙箱）**：本设计的"能力层完全仲裁 + 控制/数据平面分离 + 目标不被静默改写"已隔离控制平面，不需再上 DSL 解释器。
4. **强一致/高并发的分布式决策**：本系统语义上"一次想一件事"（像人），天然低并发；不追求分布式共识。

> 何时才重新考虑上述：只有当"简单做法"被实测证明不足、且代价确实不可接受时，才逐项【重新评估】。默认保持简单。

## 8. 开放问题（待后续讨论，非本文结论）

本文是**概念框架**，以下问题留待落地设计时逐个拍板：

1. **目标树的维护形态**：谁写、怎么写、引擎"建议新目标"的确认走什么交互；目标优先级如何量化（绝对权重 vs 相对排序）。
2. **心跳频率与打断**：正常心跳间隔、反空转降频的档位、"高优先信号打断当前节奏"的判定标准。
3. **打分权重与口径**：贡献度/可行性/成本-风险的合成公式、主体偏好如何调制权重；这些应是**配置项**（对齐 survey：不硬编码）。
4. **自主度分级的具体 tier 与能力清单**：哪些能力属哪个 tier、各 tier 的"自执行 vs 建议"规则。
5. **情景记忆的检索机制**：向量/关键词/图，召回口径，如何喂给打分做校准。
6. **感知层支持哪些模态**：MVP 先支持哪几种 Signal，多模态理解的深度。
7. **反馈闭环的"结果"如何客观化**：怎么判定一个行动"真的推进了目标"（避免又用不可靠的自评），可外部验证的成功信号从哪来。
8. **多目标冲突仲裁**：两个高优先目标争夺同一 tick 时的取舍规则（是否需要显式的目标间优先级仲裁，还是统一进候选打分）。
