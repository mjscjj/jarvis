# M3 / M5 上下文与世界投影统一方案

Status: approved implementation
Date: 2026-09-13

## 目标与职责

M3 看清现场后决定是否准入；M5 接收原始现场，独立确定目标并执行。
两者共用精简的当前世界目录，详情通过原子工具查询。

保留 M2 → M3 → Todo → Task → M5、现有表结构、状态和去重机制。
不增加判断阶段、摘要 Agent、目录数据库或内部权限系统。

| 信息 | 所有者 | 时间与使用方式 |
|---|---|---|
| 原始现场 | 来源生产者 | 原始请求、会话身份、消息关系和材料，创建时冻结 |
| 当前世界目录 | 公共 worldview 查询 | 本轮实时读取，有限索引，按需下钻 |
| 准入判断 | M3 | Todo 描述、事件与运行审计，不构成 M5 执行合同 |
| 当前目标与进展 | M5 | Task 摘要、Run 和事件，可按证据调整 |

## M3 输入与交接

默认看见来源会话、发言人、私聊对端、原始消息、回复关系、材料入口和公共世界目录。
私聊对端使用会话元数据及 Person.P2PChatID 关联；无法确定时保留未知。
机器人回复可以是现场证据，不因不能触发准入就被移除。

普通会话默认读取 24 小时内最近 50 条前文；话题读取最近 50 条，不设时间下限。
补齐新消息的 root_id、reply_to 及可解析祖先，缺失锚点显式记录。
总预算继续使用 extract.max_prompt_chars（基线 60000）。
超限优先缩小新消息批次，再按整条消息移出最旧非锚点前文；单条超大正文提供原文分段读取入口。
存储原文不截断，并记录实际展示的消息 ID、未展开消息及缺失锚点。

Candidate 控制外壳保留。title 是中性事项索引；target/action_type/project_hint 保留现有去重用途。
payload 和完整模型输出留在 M3 审计，执行包只携带原文触发引用、现场和确有消费者的关联。
多 Task 共用一段现场时，各自保留不同触发锚点，避免每个 Task 都接管整段对话。
M3 可围绕影响准入的信息缺口做最短查询，证据足够立即停止。

## 世界目录

GET /api/world-overview；CLI：get-world-overview。
参数：section、query、offset、limit、task_id（CLI 使用 --id）。
默认目录不需要参数；显式类别支持 project/key_matter/task/recent_task/todo/person/group/resource。
当前 Task ID 用于排除本 Task 及来源 Todo，不限制查询权限。

| 默认类别 | 内容与限制 |
|---|---|
| Principal | 身份、岗位、负责人及最多 200 字的首行索引 |
| Project | 活跃项目最多 10 条，角色、状态、首行索引 |
| Key matter | 未关闭事项最多 10 条，首行索引、已记录期限 |
| Task | 所有来源的未结束 Task 最多 10 条；近 7 天结束最多 5 条 |
| Todo | extracted/observing 最多 10 条，原文片段及关联 Task |
| 人物、群、资源 | 当前现场提供身份，其余通过类别查询 |

单项预览最多 80 字，省略用 … 标记。项目按既有优先级，其余按更新时间、ID 排序。
整个 JSON 目录最多 6000 Unicode 字符；超限从类别尾部轮流减少条目，保留 total/next_offset/has_more。
目录预览不是已核验事实；查不到不等于不存在。不另建摘要真源或运行时 LLM 摘要器。
get-context 保留来源背景查询职责，不作为 M3/M5 默认世界目录。

## 证据载体和读取

保留 Todo.content 与 Task.source_payload，新包写 format_version: 2：

- source：原始请求或消息触发引用。
- capture：创建时现场、范围、材料与证据读取入口。
- annotation：有出处的关联提示，不写 M3 简报或建议动作。

语义正文使用宽松 JSON；版本与引用仅服务机器读取。
Todo 事件 detail.m3_admission 保留完整 Candidate（包含未知扩展字段）。

get-task/get-todo --context evidence 使用来源无关的证据视图，默认读取也使用该视图。
source/capture/annotation/full 保留原貌读取。message-id 定位冻结消息。
offset/length 对序列化原文按 Unicode 字符分段，返回 text、next_offset、total_characters、has_more。
get-message/get-captured-resource 也支持该分段接口。

M5 现场视图预算为 30000 字符，优先触发原文、回复锚点和最近前文。
超长请求或现场字段返回大小及读取入口，不改写存储原文。

历史无版本包使用明确适配器：Todo 的旧 source 标为 M3 审计，从 capture 读取原文；
manual/scheduled 等保留原始 source。未知版本或损坏包报错，不猜测业务字段。

## M5 与各来源

首次执行/重试：Task 最小信息、原始现场、当前世界目录、用户补充、历史 Run 与 effects 入口。
同 Session 恢复：追加当前目录、状态和用户回答，不重复注入整个冻结现场。
历史上游简报只代表当时判断，已有授权和副作用记录继续有效。

M5 独立判断目标、责任、是否重复和是否行动；即使没有新事实，也可纠正上游对原文的误读。
事项标签不证明执行意图。项目关联记录出处；仅凭关联不自动选择执行仓库。
显式提供的 RepoPath 保留；其它情况由 M5 用工具核实。

| 来源 | 必须保留 |
|---|---|
| M3 | 原始现场、触发锚点、关系、短查询证据 |
| 手动/交互 | 用户完整要求、必要前文、附件、明确交付目标与约束 |
| 定时 | 完整指令、本次 occurrence、计划与实际触发时刻、调度时区、已有范围参数 |
| 主动巡视 | 原始发现、出处、关联；巡视判断不能伪装成用户要求 |

Factory 不再查询并重建世界背景。来源方准备现场，创建层机械校验、冻结、保存、幂等和唤醒。
新外部来源继续通过通用 clue 入口接入，不增加 M5 来源分支。

## 消费者与留痕

- 交办 Skill 从关联和原始交办对话核验，不依赖 M3 分类简报。
- FactEngine 区分 Todo 生命周期与业务证据，不把 M3 判断和项目推断当成已确认事实。
- 实体页首行用于目录定位；Principal 页不复制逐条 Task 日志。此次仅修正默认 Principal 索引，全面历史清理另行进行。
- 前端分别展示原文、M3 准入审计和 M5 执行记录，历史格式明确标注。
- M3 每次运行保留 prompt.txt、result.json、CLI stdout.jsonl/stderr.txt 及原始证据文件。
  CLI 记录只证明实际捕获的返回；模型评论仍是审计。原始材料位于 JARVIS_EVIDENCE_DIR。
- M5 保留每轮实际 prompt，包括本轮世界目录；不新增审计数据库。

## 切换与验收

不批量改写历史证据，不清空已有 Session；保留用户回答和 effects。
更新默认窗口配置及本机原基线值，运行相关包、全仓库测试和前端检查。
构建/重启仅使用 scripts/rebuild-server.sh，不强制中断执行中的 Task。

验收：真人私聊指代、已回复现场、多事项触发锚点、错误 M3 理由隔离、跨天根消息、
跨来源重复工作、长页面预算、原始查询材料、旧格式读取、用户交付目标、重试/恢复连续性。
确定性测试验证输入与存储；真实 Agent 回放单独验证意图理解，不把字段断言当行为证明。
