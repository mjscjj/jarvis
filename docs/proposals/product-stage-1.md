# 单人本地协作主干

> Status: proposal
> Authority: non-normative
> Last reviewed: 2026-09-11

## 目标

让 principal 不必持续打开管理后台，也能看见真正需要处理的阻塞、问题和结果，同时保持 Jarvis 的统一 Task 执行链路。

## 已实现基础

- CC Connect 可以在飞书当前会话即时处理或创建 manual Task；
- M5 的 `question` 通过飞书卡片送达并恢复同一 Session；
- `notice-principal` 可以发送幂等通知卡片；
- 晨报、日报和主动巡视已经形成固定节律；
- 工作台展示 Task、待回答问题和近期结果。

## 尚待决策

1. 是否需要一个跨 Task 的统一“待我处理”收件箱，还是继续以问题卡和工作台为入口；
2. 哪些重要结果必须主动送达，哪些只留在 Task；
3. 是否需要项目级行动面板，还是实体页 + Task 查询已经足够；
4. 如何衡量“通知有价值”而不引入固定数量配额。

## 实施原则

- 外部行动仍创建普通 Task 或由当前 M5 完成，不新增通知专用流水线；
- 通知不是 Task 状态，送达结果写 effects；
- 当前世界模型是真源，产品视图只做投影；
- 先用真实遗漏和打扰样本确定最小改动，再新增页面或状态。

## 非目标

不建设团队项目管理平台、多用户权限系统、独立消息队列或规则引擎。
