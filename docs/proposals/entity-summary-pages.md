# 实体 Summary：持续演化的当前认知页

> Status: implemented — 2026-09-13 已切换公共页面指导、FactEngine 证据投影和世界目录，并完成首轮存量页面清理。
> Date: 2026-09-13
> Authority: 当前实现以 [架构总纲](../00-overview.md)、[M1 模块](../modules/01-background.md) 和代码为准。
> Scope: 实体页维护、证据输入、M3/M5 读取与存量修复。

## 1. 目标与已对齐原则

每个实体保留一张持续更新的 Summary 页面，让不了解来龙去脉的读者能够理解：它是什么、与 Principal 有什么关系、当前处境如何，以及哪些背景会影响后续判断。

页面应随着现实变化形成越来越准确、清楚的认知。它可以包含业务进展、关系、决定、约束、风险和必要历史；由模型根据实体本身和证据自然组织，不为不同实体分别制定写作规则，不规定必填章节。

已对齐的原则：

- 所有实体共用通用指导，不增加按实体类型分支的模板或维护流程。
- 模型判断内容是否有意义、归属哪个实体、怎样表达和何时压缩；代码只保证运行所需的硬边界。
- Task 的创建、执行、等待、审批、重试、完成等运作流转留在 Task 自身记录中。
- 只有 Task 背后真正发生、与实体有关的现实事实，才按其意义更新实体页。
- 当前认知可以保留必要历史；细节逐渐压缩，完整证据与旧页面仍可追溯。
- 没有认知变化时允许不写；时间流逝不能单独证明事项完成或风险解除。
- 一份实体页是内容真源，目录从首行投影，不再维护独立简介或另一份模型摘要。

## 2. 原设计与当前偏移

2026-08-15 的 `1aa231a` 引入实体 Summary 单页化：全文读写、有长度上限、首行作为索引，页面保存当前认知，历史通过 Fact 下钻。2026-08-18 的 `08693d5` 将旧页面移入独立 PageRevision，避免模型把自己的旧认知重新当作现实证据。

这个设计不依赖固定字段，早期页面确实自然形成过当前阶段、关键决定、风险和协作关系等内容。后续文档整合保留了高层概念，但运行中的维护约束没有充分保证这种演化。

本轮核对发现的具体偏移：

1. FactEngine 按 TaskEvent 读取材料时，同时携带 Task 当前状态、Task.summary、execution_result、Run summary、output 和 effects。同一结果存在重复表达，且旧事件附带的是读取时的 Task 当前值。
2. 自动维护提示词要求“改写实体的长期事实页是本轮必做动作”，同时又允许“没有新认知时什么都不写”，两者矛盾。
3. 新增、更新和改判有明确引导，日常删除、合并与保持不变不够明确；压缩主要等到超限才发生。
4. 巡检 Skill 与自动维护提示词各自维护页面写法，容易出现不一致。
5. 存量页面已有 Task 台账，模型读取旧页后可能继续沿用其结构。

这些是可以确认的输入与指令问题。历史页面已能证明 Task 台账很早就出现，但现有留痕不足以把每次错误改写归因到某个具体 Agent 调用，不能仅凭提交时间断言唯一原因。

## 3. 信息归属

| 信息 | 真源与职责 |
|---|---|
| 实体当前认知 | 实体 Summary，表达现状、重要背景和仍影响判断的历史 |
| 原始证据 | 原始消息、资料、执行输出与 effects 等，保留出处和发生时间 |
| 证据索引 | Fact，提供主体、简短定位、时间及原始材料指针 |
| 认知历史 | PageRevision，保留改写前的完整页面；不是独立现实证据 |
| Task 当前进展 | Task.summary，供 Task 查询及本 Task 执行连续性使用 |
| Task 运作过程 | TaskEvent、Run、人工回答与 effects 等既有记录 |
| M3 的准入解释 | M3 审计，不自动成为业务事实 |
| Agent 行为要求 | 所属阶段 prompt/rules、Skill 或 shared memory，不从实体页另建行为规则真源 |

实体页中的现实状态与 Task 状态必须区分。例如“业务方尚未确认验收口径，扩大使用范围受阻”可以进入实体页；“Task 等待人工回答”本身没有证明这项业务事实。

引用 Task 可以帮助追溯证据，但引用并不意味着复制其进度。Task 被标记完成也不能独立证明业务目标完成。

## 4. 所有实体共用的写作指导

以下正文作为实施时的统一页面内容契约，不再附加按实体类型划分的写作清单：

> 维护一张关于这个对象的当前认知页，让不了解来龙去脉的读者理解它是什么、与 Principal 有什么关系、当前处境如何，以及哪些背景会影响后续判断。
>
> 根据对象本身和实际证据，自行组织内容与章节。当前进展、重要关系、决策、约束、风险和历史沿革都是可能有用的内容，不要求逐项覆盖，也不预设固定结构。
>
> 新材料到来时，结合已有全文判断是否需要新增、替换、合并或删除。保留仍然有用的认知，压缩已经结束的过程，留下解释当前处境所必需的历史。没有认知变化时保持不变；不能仅因时间过去就认定事情已经解决。
>
> 实体页只记录与该实体有关的现实事实。Task 的创建、执行、等待、审批、重试、完成等运作流转留在 Task 自身记录中；只有 Task 背后真正发生的变化，例如已确认的决定、实际交付、职责变化或业务阻塞，才按其意义更新实体页。
>
> 结论应有依据，未知与最后确认的状态要表达清楚。上游判断、重复转述和旧页面都不能代替独立证据。按相关性将事实写入合适实体，其他页面用关系和引用连接，避免复制出多份相同内容。
>
> 第一行提供简短定位，正文按需展开，详细证据通过引用追溯。页面长度服从信息价值，未受影响的正确内容保持稳定，不为填满页面或显示本轮工作量而改写。

内容少时几段自然语言即可；内容复杂时可以形成章节。示例和回放样本用于验证效果，不作为固定标题或字段清单注入模型。

## 5. 历史与时效如何演变

页面当前表达的详略随其意义变化，由模型判断，不使用固定时间阈值自动遗忘。

| 新证据与当前内容的关系 | 期望的页面演变 |
|---|---|
| 内容仍成立，且影响当前判断 | 保留，必要时补充最新依据 |
| 现实状态发生变化 | 用新状态替换旧状态，保留必要原因 |
| 事情已结束，但留下长期结果或约束 | 压缩成结果或稳定背景 |
| 旧过程已不影响当前判断 | 从当前页移出，仍通过证据和版本查询 |
| 旧判断被推翻 | 修正当前结论；旧判断仅在解释现状仍有价值时简短保留 |
| 材料仅有追溯价值 | 登记 Fact，不强制改写 Summary |
| 没有新认知，或只是重复材料 | 不写 |

例如同一件事可以依次表达为“正在验证，验收尚未通过”“验证已通过，两个团队开始使用”“当前采用此方案，原因是业务规则存在差异”。旧过程逐步压缩，仍有效的原因继续保留。

处理时效时须分清三个时间：现实发生时间、证据最后确认时间、页面写入时间。刚刚编辑页面不意味着其中全部结论刚刚被核验。

长期没有消息时，不凭沉默宣布风险解除，也不把旧阻塞不加说明地当作今日状态。对影响当前判断且可能变化的内容，保留最后确认时间和待核实边界；需要时再通过工具查询。尚未解决的承诺不能因压缩页面而被默默删除。

Fact 继续作为原始材料索引，PageRevision 继续保存旧全文。页面里的“必要历史”只承担解释作用，不另建完整时间线或历史摘要存储。

## 6. 通用指导的所有权与生效方式

通用页面指导属于实体页工具的内容契约。实施时采用一份由工具模块维护的 Markdown 正文，通过现有 `get-page/update-page` 帮助入口读取；工具目录负责提供入口，不复制全文。

正文位于 `conf/prompts/entity-page-guidance.md`，通过 textstore 的稳定 key `entity_page_guidance` 读取，并由 `get-page-guidance` 对 Agent 暴露。它是公共页面内容契约，不注册为跨阶段工作规则，也不在 Go 或多个 Skill 中复制正文。

各维护者只保留自己的职责要求：

| 维护者 | 负责什么 |
|---|---|
| FactEngine | 依据增量证据判断是否需要更新认知，完成必要写入与回读后停止 |
| 巡检 Skill | 处理陈旧、冗余、缺失和超限页面；根据证据整理全文 |
| M5 | 修正本轮亲自核实的相关认知，继续完成真实任务，不顺带展开全世界整理 |
| 其他维护者 | 根据自身任务使用同一工具与内容契约 |

这些是注意力与职责边界，不是工具权限。M3/M5 等阶段的完整有效输入必须同步检查，移除过时模板、重复正文以及“先照旧写，下游再忽略”的反向规则。

首次在会话中维护页面时应读取通用指导；同会话无需每次重复读取。指导文件缺失应明确报错，不以另一份内置正文兜底。

## 7. FactEngine 输入与维护方式

### 7.1 清理重复投影，保留完整证据

继续使用现有来源游标和通用材料协议。TaskEvent/TodoEvent 可以提供定位与变化线索，但不自动等同于实体认知变化，不按来源类型或成功失败判断长期价值。

目标材料形态为：来源指针、原始发生时间、必要的对象关联，以及一份原始证据正文或明确的读取入口。

- 去掉每条事件旁重复附带的 Task.summary、Task 当前状态和 execution_result 副本。
- 某个 Run 的原始 output 完整保留，独立保存的 effects 继续可读；不再叠加同义 Run summary 副本。
- 对同一批中重复指向同一 Run 的材料，按真实 ID 复用正文，保留各事件引用；不把多次转述当作多份证据。
- 没有 Run 的事件仍可提供其原始事件或补充材料入口，不能因此丢失人工补充等真实信息。
- 不用代码删除原始输出中的未知字段或按关键词筛选“业务事实”。输出内自带的进度描述仍是原始证据的一部分，由模型理解其性质。
- 所有原始 Task、Run 和事件记录继续保留，默认输入变薄不等于删除存储证据。

来源游标只在既有成功边界推进。材料复用不能跳过未处理证据；失败重放时保持现有幂等与引用关系。只有 ID 相同的原件可以机械合并，不新增模型相似度去重。

### 7.2 更新提示词

删除“改写页面是本轮必做动作”。阶段目标改为判断新材料是否改变已有认知，可能得到不写、只登记 Fact、更新页面并登记必要证据等结果。不得要求每份材料必须产出页面改动或 Fact。

FactEngine 先理解材料，再读取相关实体的完整页面。必要查询补足判断；证据不足时保留不确定性。更新时使用第 4 节通用指导，不另写一套实体模板。

页面没有超过上限，也可以合并和移出失去意义的旧过程。全文读取和写回是存储单位，不要求每轮重写所有未受影响的措辞。

## 8. M3/M5 的读取方式

继续沿用已实施的原始现场与当前世界目录分离设计，冻结证据不重建。

- 实体目录读取同一 Summary 的首行，完整正文通过 `get-page` 获取。
- 首行描述定位或主要处境，由维护 Agent 撰写；运行时只做有标识的长度预览，不调用模型另行总结。
- 默认 Task 目录只展示 ID、事项索引、状态、来源和关联，不再携带 Task.summary 或执行结果。
- Todo 目录保持事项与原文索引，不将 M3 准入解释展示为已确认事实。
- M5 当前 Task 自己的 Task.summary 继续用于执行连续性；它与其他工作的目录是不同读取用途。
- 判重或核验进展时使用 `get-task/get-todo` 及历史工具。目录未列出某项不代表它不存在。
- 完整页面中的动态结论按其证据时间理解；查询新状态不覆盖创建时冻结材料。

目录预算、数量上限和分页机制继续使用既有配置，本次不再调整一组新的数字。

## 9. 存储与最小运行边界

继续使用现有实体 Summary、Fact、PageRevision、Task、Run 和事件表，不新增语义字段或数据库表。

保留 `update-page` 唯一正文写入口、现有 8000 字符上限、真实引用校验、并发冲突检测、版本留痕和写后回读。8000 是保护上限，不是写作目标。

不增加固定章节校验、实体类型模板、Task 关键词禁用、自动过期规则、摘要 Agent、独立规划阶段或内部权限系统。没有内容变化时避免无意义写入及推进页面时间。

PageRevision 继续保存旧正文，不把旧版页面当作 Fact 回灌。历史查询若存在工具入口缺口，应复用现有版本存储补齐读取能力，不新增第二份历史正文。

## 10. 存量页面修复

先修维护契约与输入，再修页面，避免修复后立即被旧流程重新污染。

按页面当前重要性、失真程度和证据可获得性安排修复，不按实体类型增加专用重写规则。每页使用同一通用指导：

1. 读取当前全文、关联实体及必要原始证据。
2. 分清现实状态、历史背景、上游推断和 Task 运作记录。
3. 移出运作台账，把有证据支持的真实变化归回相关认知。
4. 修正旧结论，保留重要风险、承诺、约束和必要历史；无法核实的内容表达证据边界。
5. 按当前版本写回并回读，旧全文由既有 PageRevision 保存。

早期优秀页面只能提供结构参考，不能直接当作当前事实恢复。移除 Task 台账不等于删除 Task，也不修改原始证据和执行记录。不得以任意关键字批量删除整段页面。

## 11. 验证与留痕

### 确定性验证

- 默认 Task 目录不再含 summary 和执行结果，本 Task 的进展与历史入口仍存在。
- FactEngine 不再向每个旧事件附带读取时的 Task 当前进度；原始材料与未知字段没有丢失。
- 同一 Run 的材料复用保持指针、时间、effects、游标及失败重放正确。
- 通用指导只有一份内容真源，各维护入口可以读到；最终提示词不再要求每轮必须改页，也不包含按实体类型的模板。
- 页面引用、长度、并发冲突、无变化写入及 PageRevision 回归通过。

### Agent 行为回放

采用固定证据、模拟或只读外部工具，在隔离页面数据上验证连续演化，不以字符串或章节名称断言代替内容质量判断。

| 场景 | 验收要点 |
|---|---|
| 只有 Task 创建、重试、等待、完成记录 | 实体页不新增运作台账 |
| Task 背后确认了真实交付 | 按与实体的关系记录交付带来的现状变化 |
| Task 失败但发现有效业务约束 | 不因失败状态丢弃真实发现 |
| 风险出现后有证据证明解除 | 当前风险更新或移出，必要结果和历史可查 |
| 长期无新消息 | 不凭沉默认定完成，不把最后确认时间改成今天 |
| 新证据推翻旧判断 | 当前结论修正，旧页面保留，重复转述不增加可信度 |
| 相同证据多次进入 | 页面不重复扩张 |
| 多轮推进后事情稳定 | 中间过程逐步压缩，关键决定、约束和未结承诺不丢 |
| 不同形态的对象 | 模型自行组织表达，无需修改实体写作模板或 Go 分支 |
| 新内容适合已有其他实体 | 正确归属并引用，不把所有变化堆入 Principal 页 |

FactEngine 应使用现有运行文件方式保留实际 prompt、材料范围、原始输出和工具事件流，避免临时目录删除后无法复盘。记录引用不冒充已保存的完整工具响应。M5 延续已有 Run 留痕；不增加审计数据库。

## 12. 实施顺序与交付边界

1. 落实公共页面指导及工具读取入口，调整 FactEngine、M5、巡检 Skill 的职责描述。
2. 清理 FactEngine 重复输入，验证证据、时间、来源游标和重放。
3. 精简 M3/M5 的 Task 目录，保留当前 Task 执行连续性。
4. 完成相关回归和连续证据回放，检查完整有效输入。
5. 切换新维护方式，再对存量页面进行有证据的修复与回读。
6. 将稳定契约合并进当前架构与模块文档；实施提案按仓库文档规范收尾，历史由 Git 保存。

实施涉及构建或重启主服务时使用 `./scripts/rebuild-server.sh`。首轮存量清理遵守单轮最多 12 页的维护边界；其余历史页面继续按相同契约分轮整理，不改变原始事实和旧版页面记录。

最终应达到：同一实体经过多轮更新，页面依然能够清楚解释当前处境，重要历史可追溯，Task 运作过程留在原有载体中；新增对象形态不需要增加专用写作规则。
