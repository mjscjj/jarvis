# Jarvis 世界模型 3D 视图方案

> Status: proposal
> Authority: non-normative
> Last verified: 2026-09-06 @ 250bbdb
> Scope: 只设计，不代表已实现

## 1. 结论

在现有 Jarvis 管理后台的「世界」页面中增加一个只读的「世界地图」页签，使用开源的 `react-force-graph-3d` 与 Three.js 渲染。3D 只承担展示和交互，不拥有实体、关系或事实语义。

第一版只改前端：复用现有 `GET /api/pages` 和 `GET /api/pages/:type/:id`，不新增数据库、表、同步任务或 3D 专用后端协议。若真实测量证明现有接口成为性能瓶颈，再单独讨论通用批量读取能力，不在本方案中预先增加。

## 2. 目标与非目标

### 2.1 目标

- 从真实数据库实时生成可旋转、缩放、点击的 3D 关系图，不使用固定演示数据。
- 默认展示当前活跃世界，并能按实体类型筛选。
- 能搜索全量实体；命中冷数据或归档实体时，按需展示它的一跳邻域。
- 点击节点后稳定聚焦，突出直接关系，并在右侧查看当前摘要、事实数量和引用。
- 在当前本地单用户规模下保持流畅、可读、可恢复，不把画面做成不可用的“毛线团”。

### 2.2 非目标

- 不开发 WebGL、力导向布局或 3D 相机引擎。
- 不引入 Obsidian、图数据库、GraphXR 或数据导出副本。
- 不把 Fact、Todo、Task 全部建模成图节点。
- 不在第一版加入 VR、AR、多套布局编辑器、图算法工作台或世界模型写入能力。
- 不从引用文本推断“Owner”“依赖”“负责”等强关系；没有权威语义时统一显示为引用。

## 3. 语义所有权与数据链路

### 3.1 权威来源

| 展示内容 | 权威来源 | 3D 层行为 |
|---|---|---|
| 实体集合与活跃范围 | `background.PageService.ListPages` | 读取并投影，不重定义活跃规则 |
| 实体名称与长期状态 | `PageIndexItem` / `PageView.summary` | 作为标签和详情正文 |
| 实体关系 | `PageView.outgoing` / `PageView.backlinks` | 只画明确 Markdown 引用 |
| 事实数量 | `PageView.fact_count` | 只用于元信息和有限的节点尺寸编码 |
| 实体类型 | principal / person / project / key_matter / group / resource | 固定颜色与筛选项 |
| 认证与可见范围 | 现有浏览器会话与 API 中间件 | 不绕过、不增加公开数据入口 |

关系继续由实体页中的 `[名称](type:id)` 引用产生。3D 页面不维护关系表，不修改正文，也不缓存一份可独立演进的世界状态。

### 3.2 运行时读取

1. 页面进入时调用 `GET /api/pages`，取得当前活跃索引。
2. 以固定并发上限（建议 8）读取活跃实体的 `PageView`，拼出活跃全局图。
3. 同时或空闲时调用 `GET /api/pages?all=true` 取得全量轻量索引，只用于搜索，不读取全部详情。
4. 搜索命中非活跃实体时，只读取该实体详情；用它的出链和反链直接构造一跳星形图。
5. 用户继续点击邻居时再读取邻居详情，并合并到当前内存图。
6. 刷新按钮清空本页内存缓存并重新读取；离开页面后不持久化图数据。

2026-09-06 本机观测值为活跃 119 个、全量索引 5,283 个。数值只用于容量设计，页面不得硬编码。

## 4. 开源技术选型

### 4.1 采用

- [`react-force-graph-3d`](https://github.com/vasturiano/react-force-graph)：React 封装、力导向图、命中检测、拖拽、镜头与图生命周期。
- [`three`](https://github.com/mrdoob/three.js)：节点材质、选中环、灯光和必要的自定义 Object3D。
- [`three-spritetext`](https://github.com/vasturiano/three-spritetext)：面向相机的节点标签。

实现时固定精确版本并提交 lockfile，核对各包许可证；依赖全部从 npm 安装，不使用运行时 CDN。

### 4.2 为什么不换成更重的方案

- Reagraph 的多布局能力很好，但本需求只需要一个可读的 3D 力导向视图，迁移到另一套图模型没有当前收益。
- 自定义 React Three Fiber 能获得更自由的视觉效果，但会把布局、命中、相机和图生命周期重新变成项目代码。
- Obsidian 插件需要生成 Vault 副本，会引入同步和双真源问题。
- 商业图谱产品会扩大部署、授权和数据边界，不符合本地 MVP。

## 5. 产品形态

### 5.1 页面入口

在现有「世界」页面的一级内容区增加「世界地图」页签，与「我的资料 / 项目 / 人物 / 会话 / 资源 / 关键事项 / 全部事实」并列。组件使用动态导入，未进入世界地图时不加载 Three.js 大包。

不增加独立主导航，不增加公开 demo 路由。

### 5.2 页面布局

- 顶部：搜索框、视图范围、刷新和适应画布。
- 左侧：实体类型筛选及各类型数量。
- 中央：3D 图画布。
- 右侧：选中实体的摘要、类型、更新时间、事实数、出链、反链和可点击邻居。
- 底部：自动旋转、关系方向、当前可见节点/关系数量。

页面视觉定位为“语义观测台”，不是太空游戏：深色背景、有限光效、清楚的类型颜色和状态层级优先于装饰。

## 6. 视图与交互

### 6.1 两种范围

| 范围 | 内容 | 使用场景 |
|---|---|---|
| 活跃全局 | `GET /api/pages` 返回的全部活跃实体及其相互引用 | 看整体结构、项目与协作面 |
| 一跳聚焦 | 选中实体、它的出链和反链邻居 | 查询具体人、项目、事项和历史实体 |

第一版不做两跳开关。用户可以从右侧邻居继续点击，逐步探索；这样比一次展开两跳更可控。

### 6.2 筛选与搜索

- 类型筛选支持 principal、person、project、key_matter、group、resource，可多选或一键清空。
- 搜索同时匹配名称与索引摘要，结果中标明类型和是否属于当前活跃集。
- 搜索结果按名称精确匹配、前缀匹配、包含匹配、摘要匹配排序。
- 选中搜索结果后进入一跳聚焦，清空搜索框，但不触发自动全图缩放覆盖聚焦镜头。
- 没有匹配、读取失败和无关系实体都提供明确状态，不显示空白画布。

### 6.3 点击与镜头

- 单击节点：选中、打开详情、突出一跳关系并平滑聚焦。
- 单击详情中的邻居：跳转到该邻居；未加载时按需读取。
- 拖动背景旋转、滚轮缩放、右键或修饰键平移；节点拖动仅改变当前临时布局。
- `Esc` 清除选中并回到当前范围；“适应画布”只由用户显式触发，或在首次布局稳定后触发一次。
- 聚焦距离根据节点半径、视口高度和相机 FOV 计算，使不同大小节点在屏幕上的占用接近，而不是使用固定世界距离。

## 7. 视觉编码

### 7.1 节点

- 每种实体类型使用一套固定且可区分的颜色；颜色只表达类型，不表达模型猜测的状态。
- 节点尺寸使用 `log2(fact_count + 1)`，并设置严格上下限，避免事实多的节点吞没画面。
- 选中节点增加细光环；邻居保持正常亮度；无关节点降低透明度但不完全消失。
- 球体分段保持适中，避免为了圆滑增加不必要的 GPU 开销。

### 7.2 标签

- 默认只保证选中节点、悬停节点和直接邻居标签可见。
- 其它标签根据相机距离分级显隐；远距离不绘制全量名称。
- 标签始终面向相机，选中标签不被球体遮挡。
- 关系名称默认只显示在选中节点的直接关系上。

### 7.3 关系

- 出链使用箭头表示方向；反链在数据层仍保持真实 source → target。
- 选中关系加亮，可使用少量流动粒子提示方向；非选中关系用低对比细线。
- 重复引用按 source/target 去重，但不把双向引用合并成一条无向边。
- 关系文案使用“引用”；只有后端未来提供权威关系语义时才显示更具体名称。

## 8. 性能与稳定性边界

- 活跃全局只加载默认工作集，不把 5,283 个实体的详情同时拉到浏览器。
- 全量索引只保存搜索所需字段；历史实体详情按需加载。
- 页面内用 `Map<type:id, PageView>` 缓存已读取实体，避免重复请求。
- 并发请求有上限并支持 `AbortSignal`；切换页面或刷新时取消旧请求。
- 力模拟稳定后停止持续计算；自动旋转关闭时不维持无意义动画。
- 自定义 Three.js 几何体和材质复用，并在卸载时释放，避免重复选择造成显存泄漏。
- 画布尺寸由 `ResizeObserver` 驱动；窄窗口收起左侧筛选，详情改为抽屉。
- WebGL 初始化失败时显示原因和返回现有实体列表页的入口，不做静默空白降级。

## 9. 代码边界

预计修改：

- `web/package.json`、`web/package-lock.json`：增加并固定开源依赖。
- `web/src/types.ts`：补齐 `PageIndexItem` 等已有 API 的前端类型。
- `web/src/api.ts`：增加 `listPages` 只读封装。
- `web/src/Background.tsx`：注册「世界地图」页签和懒加载入口。
- `web/src/world-map/WorldMap.tsx`：页面状态与交互编排。
- `web/src/world-map/graphData.ts`：纯数据投影、邻域和筛选逻辑。
- `web/src/world-map/camera.ts`：纯镜头距离计算。
- `web/src/world-map/world-map.css`：布局和视觉样式。
- `web/test/worldMapData.test.ts`：数据投影、关系去重、筛选和邻域单测。
- `web/e2e/world-map.spec.js`：真实登录环境下的关键交互回归；若仓库决定不引入 Playwright，则使用现有浏览器验收流程，不为一页单独引入第二套测试框架。

第一版不修改 `internal/`、`cmd/`、数据库模型和 API 路由。

## 10. 实施顺序

1. **数据切片**：接通真实 Pages API，先用普通列表验证实体数、引用方向和历史搜索。
2. **基础 3D**：接入懒加载图组件，完成类型颜色、受限节点尺寸和首次适应画布。
3. **可用交互**：加入筛选、搜索、一跳聚焦、详情跳转和稳定镜头。
4. **视觉降噪**：完成标签 LOD、非邻居淡化、选中光环和关系方向。
5. **稳定性**：请求取消、缓存释放、窗口响应、错误状态和构建体积检查。
6. **验收**：单测、类型检查、生产构建和真实数据浏览器回归全部通过后再提交实现。

每一步都保持页面可运行，不引入“先重构所有世界 API 再画图”的前置工程。

## 11. 验收标准

- 页面数据全部来自当前 Jarvis API，源码中没有业务演示实体。
- 活跃全局节点数与无过滤 `GET /api/pages` 同步，数据库变化后刷新可见。
- 可以搜索 `all=true` 索引中的非活跃实体，并打开其真实一跳关系。
- 六种实体类型均可筛选，清空筛选可恢复全局。
- 点击不同尺寸和不同位置的节点后，目标保持在可读尺度且详情一致。
- 选中节点时可以区分出链、反链和无关关系，不伪造强关系语义。
- 当前本机活跃规模首次可交互目标不超过 3 秒；若未达到，先记录网络与渲染分段耗时，再决定是否需要后端批量能力。
- 连续切换 50 个节点不持续增长 Three.js 对象和事件监听器。
- 退出页面后不继续执行力模拟或网络请求。
- 页面只有读取副作用，不产生数据库写入。
- `npm run typecheck`、`npm test`、`npm run build` 和 `git diff --check` 通过。

## 12. 风险与停止条件

| 风险 | 处理 |
|---|---|
| 活跃实体详情请求过多 | 先以并发上限和缓存验证；只有测量不达标才讨论通用批量读取 |
| 全图成为毛线团 | 默认活跃集、类型筛选、一跳聚焦、标签 LOD，不靠继续缩小节点解决 |
| 大节点点击后过近 | 使用投影尺寸驱动的相机距离，并与自动 fit 动作互斥 |
| 关系被误读为业务语义 | 只显示权威引用方向，统一命名“引用” |
| 视觉效果挤压可读性 | 光效仅用于选中和方向提示，任何装饰不得覆盖标签、命中或详情 |
| 依赖体积影响管理后台 | 路由级动态导入；未进入世界地图不下载 3D chunk |

出现以下任一情况时暂停实现并重新确认，而不是继续加兼容层：

- 需要让 3D 页面直接编辑世界模型；
- 必须默认同时渲染全部历史实体；
- 必须增加图算法、固定空间布局或可保存的人工排版；
- 现有 Pages API 经测量无法满足读取性能，需要修改后端协议。
