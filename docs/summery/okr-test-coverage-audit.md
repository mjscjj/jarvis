# OKR 测试覆盖盘点（2026-09-14）

本盘点区分“有自动测试”和“用真实储节节身份验收过”。两者不能合并统计。测试浏览器没有继承用户日常 Chrome 会话；本轮使用现有授权经飞书实时核身后签发短时测试会话，完成登录后的真实业务路径。设备登录本身没有因此得到验证。实际结果见[2026-09-14 真实验收记录](2026-09-14-okr-real-path-acceptance.md)。

| 能力 | 已有测试及实际性质 | 主要缺口与下一项用例 |
|---|---|---|
| 网页登录与会话 | `internal/okrworkspace/auth/*_test.go`、`internal/api/okr_identity_test.go` 用本地会话和模拟 OAuth；`web/test/auth.test.ts` 检查前端错误恢复 | 真实用户登录、刷新／重启后保留会话、会话失效后的写入拒绝需在最终域名验收；不能用测试会话证明本人可用 |
| 评论读写 | `internal/okrworkspace/comments_test.go` 覆盖作者、回复、编辑、删除、版本冲突和目标范围；`okrCommentFeedback.browser.mjs` 在隔离实例写无 @ 评论 | 最终部署域名下本人发布后刷新、解决／历史、目标切换、Plan 与周报入口未稳定纳入每轮发布检查；新增 `okrRealPath.browser.mjs` 执行 Review／周报／临时 Plan 的评论主路径 |
| @ 与通知 | 服务和投递测试覆盖参数、部分失败及幂等；旧浏览器脚本未发送真实通知 | 新真实脚本可搜索、选中并 @ 本人，核对投递状态和消息 ID；本人收件箱与卡片跳转仍须额外回读，结果分别记录评论与投递 |
| 导出文档 | `internal/api/okr_document_test.go` 验证测试用户 A/B 凭证选择与刷新；`OKR_BROWSER_EXPORT_ONLY=1` 返回模拟文档链接 | 本人真实页面点击、飞书文档创建、归属、正文回读缺失；新增真实入口覆盖 Review／周报点击和返回链接，飞书归属／正文仍须回读 |
| Review／周报数据 | 服务测试覆盖模板、评分、周数据、标签、进展和并发；`okrWorkflow.browser.mjs` 用隔离库操作部分页面 | 同周模板切换、保存后刷新、跨周边界、多人同时修改与真实身份仍需按变更影响面运行；主流程没有自动进入 `npm test` |
| Plan 与负责人 | 计划、定义、排序、人员和 API 测试较多，浏览器工作流也有 Plan 创建与编辑 | 新真实脚本用临时 Plan 检查目标／KR 创建、优先级、本人 Owner 保存及评论，结束后删除；旧身份数据联动仍缺少专项验收 |
| 图片与附件 | 前端图片压缩、后端存储测试覆盖本地处理 | 浏览器粘贴／上传、查看、文档导出及页面刷新后的图片回读没有真实链路验收 |
| 区域对齐、跟进、Agent 动作 | 各自服务和前端函数有测试 | 开发预览与主服务功能可能不一致；按实际部署入口逐项记录页面和后端结果，不用主服务的测试替代开发预览 |

最优先补的是一个稳定发布门：真实身份、评论、导出、@ 本人、部署后回读。现已把原模拟浏览器案例中的导航、人员目录、Review／周报／Plan 评论、Review／周报导出和本人 @ 改写成真实浏览器用例；主站已执行：评论、导出归属和正文通过；@ 已送达本人，但卡片链接落到 `/dev/`，本项未通过。真实执行可复用经飞书实时核验的本人既有授权来签发短时测试会话；这种运行不覆盖产品设备登录。其余业务场景按本表扩展。`npm test` 的数量只说明 TypeScript 单测通过；浏览器脚本以及被环境变量跳过的 Go 浏览器测试必须单独列出运行状态。

旧的模拟测试保留，用于快速覆盖错误分支和并发；其中浏览器工作流的 `Jarvis` 是测试程序注入的虚构会话。不能简单把它改名为“储节节”后称为真实测试。真实身份只从网页登录会话与飞书授权读取，使用 [真实路径测试规范](okr-real-path-testing-standard.md) 中的执行和报告口径。
