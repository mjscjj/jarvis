## 已实现

1. 默认进入首个「对话」Tab，查看会话列表、正文和底部输入区。
2. 点「新对话」，选择数据来源、Agent、模型；模型弹层先显示 5 个，支持搜索全部。
3. 输入文字或添加图片/文件并发送；正式页面调用所选 Agent，支持流式回复与停止。
4. 切换会话、搜索历史、行内改名、刷新页面，确认文字历史和独立草稿保留。
5. 在有历史的会话切换 Agent，体验“携带记录新建会话”；旧会话仍然可读。
6. 点击附件预览、下载文件或导出会话；窄屏打开历史抽屉。

交互原型仍只保存演示数据；正式页面使用 SQLite 保存会话、消息、来源和草稿，附件保存在 `data/chat/`。

## 已执行验证

2026-09-10：JavaScript 语法检查通过；Playwright / Chromium 验证了模型前 5 项/全部/搜索、来源选择、图片上传/预览/原件下载、跨会话生成与独立草稿、切 Agent 携带历史、行内改名、刷新恢复、历史搜索、Markdown 导出、停止与归档恢复。1440×960、1024×768、390×844 无横向溢出，无浏览器脚本错误。

只读模型发现成功：Codex、TRAE、Cursor 均返回当前账号可用目录；数量由源头变化，不写死。2026-09-11 又实际运行了三个 CLI 的新会话：Codex、TRAE、Cursor 均按接入协议返回预期文本；Cursor 的 stdin 与流事件差异已纳入适配器和测试。

## 实施取舍

第一版已经完成持久会话与第一 Tab、三个 Agent 和动态模型、数据来源与输入附件闭环。模型面板把源头顺序的前五项作为推荐浏览，并保留全部搜索；切换 Agent 时复制可见历史到新会话，不复用不兼容的原生 thread。

后续增强以 `design.md` 为依据：持久化 run/event 后的断线续订、工具活动卡片、Agent 生成产物登记与下载、附件预览器，以及更细的业务对象选择器。
