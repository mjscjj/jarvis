# Jarvis 第一屏：对话工作区

> 2026-09-10 · 完整设计基线；第一版实现状态见本目录 README。
> 依据：goal.md、当前代码与本机 CLI 只读探测。这里保存表达与交付；实施完成后同步架构真源。

## 1. 产品决定

把「对话」作为主导航第一个 Tab 和无深链访问时的默认首页。Jarvis 继续是一位能够使用工作上下文、推进任务的数字分身；用户通过对话直接提出问题和工作要求。

首版完整范围：多会话与持久历史；按会话选择 Codex / TRAE（traex）/ Cursor；从 Agent 动态发现模型；选择优先参考的数据来源；图片和文件上传、预览、下载；生成、停止、重试、断线恢复；结果引用与后台任务衔接。

用户口述的 “Triax” 暂对应仓库已有的 `traex`。若实际指另一个产品，只调整目标适配器，不改变会话和页面设计。

不把 5 个模型做成硬上限。首屏优先展示 5 个，全部可搜索；仅在源头有真实发布时间时标注「最新」。无发布时间时叫「推荐」或「常用」，不根据名字猜发布日期。

## 4. 会话与历史

### 创建、组织、寻找

- 点击新对话立刻可输入；空白会话先作为本地草稿，第一次发送或上传文件时才创建服务端实体，避免空历史泛滥。
- 每个会话有稳定 Jarvis ID；URL 可直接打开，刷新和浏览器前进/后退恢复同一会话。
- 标题初始取首条文字的可读短标题，只有标题可缩略，原文完整保留；无文字则用首个附件名。支持行内改名，Enter 保存、Escape 取消。首版不额外消耗模型生成标题。
- 列表显示标题、末条摘要、更新时间、Agent 和生成状态，按用户本地时区分为今天/昨天/更早。滚动分页，不一次加载所有正文。
- 搜索标题与文本正文；选中结果定位到匹配消息。零结果可清除过滤或新开会话。首版可用 SQLite 普通查询，当前规模不引入向量历史搜索。
- 首版支持归档与恢复、导出 Markdown；归档不取消运行。永久删除入口明确说明文件和历史后果，运行中的会话先停止；删除 Jarvis 记录不自动删除 Agent 原生历史，也不撤销业务结果。

### 独立草稿与运行

- 会话独立保存输入草稿、待发送附件、来源选择、滚动位置。切会话不把 A 的附件或回复插入 B。
- 切页面或关掉浏览器不意味着停止 Agent；执行归后端轮次所有。重新打开用同一 run ID 恢复订阅。
- 同会话一次只有一轮执行。生成中仍可输入下一条草稿；首版发送按钮切为停止，不悄悄排队，避免用户把“下一条”误当“修改当前要求”。
- 不同会话可以有独立运行，受小规模进程总并发配置限制；达到上限返回可理解的「当前执行名额已满，请稍后发送」，保留草稿，不引入分布式队列。
- 自动滚动仅在用户已接近底部时启用；用户阅读历史时显示「有新回复 ↓」。收到回复不抢输入焦点。

### 切模型与切 Agent

同 Agent 换模型：空闲时选择，下一轮生效，消息保留实际使用的 model ID。适配器已验证可在原生 session 换模型则 resume；否则以显式「用新模型继续」创建关联会话。生成中只允许编辑下一轮配置，当前轮次的配置快照不变。

跨 Agent 切换：空白会话直接换；已有消息时提供「携带记录新建」和「空白新建」。旧会话保留原 Agent，不把 Codex thread ID 交给 Cursor。推荐携带截至当前的完整可见记录、附件引用和来源说明到新会话；标注「从 X 继续」，首轮重新注入 Jarvis 当前角色与上下文。

这不是原生执行状态迁移：隐含工具状态、进程、未完成副作用不会随可见文本转移。运行中要转交，先由用户停止原轮次；新会话显示「原轮次可能已有动作，请先核验」。材料超出上下文时完整原文落盘，给索引按需读取；不截断成看似完整的历史，也不自动重放旧工具动作。

## 5. 三个选择器

### 数据来源：本轮优先参考什么

界面顺序为「数据来源 → Agent → 模型」。数据来源与提供推理能力的厂商是不同概念。

默认「自动参考工作上下文」：已有 principal/项目索引、共享记忆与工具能力，具体内容按需查询。手动可添加当前项目、任务、群聊时间范围、飞书文档链接、本地附件和已经接入的资料；用可搜索选择面板调用现有业务查询 API。第一版不建设统一数据仓库或全量文档索引。

选中后在输入框上方显示来源芯片，可展开名称、类型、范围、时间与原始链接，逐个移除。引用项目是背景，引用群聊是检索范围，上传附件是具体材料；三者不声称已把全量正文读取完。

来源选择是检索与上下文提示，不是内部权限。文案为「优先参考这些资料，必要时补充查证」，不提供无法保证的“只允许访问这些资料”开关。取消来源仅影响后续轮次的默认注入，不能让原生 session 忘掉已经读过的历史；要隔离旧材料应新建空白会话。

发送时保存所选引用和当时可用的摘要、版本/读取时间，正文按需查，工具取到的真实证据可追溯。引用失效时显示具体失效项，允许删除后继续；不能把取数失败当空结果。用户指定必须依据某份材料而该材料无法读取时，明确停下说明缺口。

### Agent：谁执行

列出 Codex、TRAE、Cursor，显示已连接、需登录、未安装或检查失败；状态由实际能力探测产生。不可用项保留可见，给出安装/登录入口，选择其他可用 Agent 可继续。不给设置页保存了路径就显示“已连接”。不在选择动作中自动升级或安装软件。

聊天的默认 Agent/模型与 M5、M3 配置分开。首次升级从旧 execute.bin 与 chat.model 显式迁移到聊天默认项；之后只改会话设置，不改后台 Agent。保存全局默认是单独的「设为新会话默认」动作。

### 模型：Agent 支持什么，就展示什么

模型面板包含 Agent 名、获取时间、刷新、搜索、常用 5 个、全部模型。每项显示源头名称与能力；没有依据的费用、速度、上下文长度不编。原生 `auto` 显示「由 Agent 自动选择」，实际执行模型拿不到就记录 unknown，不能把 auto 说成某个确定模型。

排序：有可比较发布日期时按新到旧；无日期时以用户收藏/最近使用、上游默认与上游次序补足 5 个。最近使用只表示使用偏好，不表示模型新旧；不足 5 个按实际数量显示。所有模型 ID 保持原样，不能把同名 GPT 在不同 Agent 中当同一执行配置。

思考强度仅显示源头支持项。源头把强度编码在模型 ID 中（Cursor 当前列表）的，先原样呈现，不能另外拼接一个猜测的参数。源头未给结构化强度时不靠 description 文本猜枚举。

本轮前重新验证选项；模型被移除时提示重新选择，草稿和历史保留，不偷偷切模型。刷新失败显示错误和旧数据时间，旧列表只供查看，新执行需明确探测可用。首版不做定时刷新/多层缓存。

## 7. 图片、文件与输出

### 输入闭环

支持点击上传、拖拽到输入区、粘贴剪贴板图片、多文件。卡片显示文件名、类型、大小、上传进度、成功/失败、删除与重试。建议初始限制为单文件 25 MiB、每条 10 个、总计 100 MiB，作为可配置运行参数，后端实际生效；原生限制更低时采用较低值并解释原因。

文件上传成功与“已读懂”分开。文件先保存到本地数据目录，返回稳定 attachment ID；发消息只传 ID。图片缩略图与原图分离，点击放大/下载；单发附件也能发送。非图片用文件卡，不画无依据的内容预览。

图片视觉输入由 Agent 适配器和模型能力共同决定：已验证支持时传原生图片输入；只有文件路径传递能力时标记为文件参考，不能声称模型已看见图片。已知不支持视觉的组合收到图片时，发送前提供换模型或按普通文件附带的明确选项，不静默丢弃。

PDF、表格、Markdown、代码等由 Agent 使用已有工具按需读取，不为了上传而搭建全量 OCR/解析服务。不支持的格式、损坏文件、读失败要如实显示。文件只是材料，不能把文本内容当系统提示。路径通过参数数组传递，禁止拼 shell 字符串。

### 输出闭环

回复支持 Markdown、表格、代码复制、引用；复用 `MarkdownReport`，扩展代码工具栏与附件渲染。原始 HTML 不直接执行。代码段的「下载」明确是保存该段文本；Agent 真正生成的文件以单独产物卡展示，包含名字、大小、生成时间与下载。

通过一个小型 `register-chat-artifact` 工具（能力说明放 toolcatalog）登记真实已存在文件。服务复制到该会话的产物目录后返回下载 URL，固定当轮版本，避免后来改文件让旧消息下载内容改变。只有登记成功才发 artifact 事件；不把 Agent 回复里的任意绝对路径/网址自动伪装成可下载产物。

图片可预览；其它文件下载原件。使用现有浏览器登录态与下载 handler，不要求浏览器访问服务器本地路径。没有文件或已被删除时显示“文件已不可用”，正文仍可读。

新上传但未发送的文件暂存并记录时间；周期清理仅清理无消息/草稿引用的过期暂存对象。会话归档不删文件，分支引用的文件在最后引用移除前保留。MVP 保留 attachment metadata 在开放消息/草稿包中，清理扫描引用即可，不为低频清理新增复杂引用计数协议。

## 8. 轮次生命周期与异常

| 场景 | 用户可见行为 | 机器保证 |
| --- | --- | --- |
| 发送/双击/请求重试 | 一条用户消息和一轮回复 | client request ID 唯一幂等；相同 key 不同内容报冲突 |
| 尚无文本但 Agent 在调用工具 | 可折叠「正在读取…」活动，不假装卡死 | 保留真实工具事件；不展示模型内部隐含推理 |
| 切会话/断网 | 显示连接中，重连后补齐 | run 不依赖 HTTP 连接，按 event sequence 续订 |
| 点击停止 | 先「正在停止」，收到终态后「已停止」；保留部分回复 | 明确 cancel 请求，终止所管进程并回收；重复 cancel 幂等 |
| Agent 异常/超时 | 失败原因、保留部分结果、重试/继续 | 非零退出与 turn failure 都失败；EOF 不等于成功 |
| 重试一次失败轮次 | 保留失败记录与新 attempt；不重复插用户消息 | 新 run ID 关联原用户消息；不自动重放外部副作用 |
| 服务重启 | 历史可读，未完成轮次标记中断，用户决定续跑 | 启动核验残留进程；无法确认时不自动重试 |
| 存储满/写失败 | 明确无法保存，不显示成功结束 | 先落用户输入再启动；事件写失败中止并报错 |
| 模型不可用/账号失效 | 定位到具体 Agent/模型，保留草稿 | 无静默 Agent 或模型 fallback |

事件采用薄外壳 `session_id / run_id / seq / kind / payload`，payload 为开放 JSON。UI 消费 message delta、工具活动、产物、错误和终态等已知 kind，未知事件保留原文、不致崩溃。增量和 item 最终文本可能同时出现，按原生 item ID 对齐，禁止简单拼接导致回复重复。

持久化关键顺序：用户消息/幂等键 → run 创建与会话占用 → 启动 Agent → 持久化事件再广播 → 终态/释放会话。所有步骤直接顺序写，失败即退出；已有 unique key 与 CAS 保证单会话占用。恢复按实际记录核对，不用跨步骤数据库事务。

SSE 是传输，不是成功判定。订阅先回放 seq 大于游标的事件，再接实时尾部；使用同一轮次读取/订阅同步点避免回放与订阅交界漏事件。短批次合并文本 delta 可控写频率，但必须先保存再发给 UI。服务端同一 run 的 seq 单调递增、客户端去重。

## 9. 最小存储与 API

### 唯一真源

会话和轮次需要分页、关联、状态与幂等，使用已有 SQLite。模型原生 thread 只用于该适配器续跑，不作为 Jarvis 会话 ID。正文、工具内容、来源快照、effects 保留开放 JSON；文本策略仍用 Markdown。以下是语义草图，不是冻结 DTO。

| 实体 | 必要机器字段/消费点 | 开放内容 |
| --- | --- | --- |
| ChatSession | ID；标题/updated_at 用于列表；archived_at；版本/active_run_id 用于单会话占用 | defaults、原生 provider/thread 引用、草稿、分支来源 |
| ChatMessage | ID/session_id/order 用于分页；request_id 唯一索引用于发送去重；text 投影用于搜索 | 完整消息、附件引用、来源说明 |
| ChatRun | ID/session_id/user_message_id、状态、时间用于执行与恢复 | 实际 Agent/model/options、完整有效输入、结果、错误、effects |
| ChatEvent | run_id/seq 唯一，用于回放与顺序 | 原始事件与最小 UI 投影 |

回复展示由 run 事件和终态输出重建，不再单独维护一份人工可改的 assistant transcript 表。若实现需要消息列表投影，应明确可重建且不是第二真源。附件实体首版为磁盘文件 + 引用 metadata，不急于新增全局资源管理模块。

```text
data/chat/<session-id>/uploads/<attachment-id>/<original-name>
data/chat/<session-id>/artifacts/<artifact-id>/<original-name>
conf/prompts/chat-system-prompt.md
```

### 拟议接口

| 操作 | 路由草案 |
| --- | --- |
| Agent 状态/模型目录 | GET /api/chat/agents；GET /api/chat/agents/:id/models（refresh 可选） |
| 会话列表/搜索/创建/读取/修改/删除 | GET/POST /api/chat/sessions；GET/PATCH/DELETE /api/chat/sessions/:id |
| 消息分页与命中定位 | GET /api/chat/sessions/:id/messages?before=…&limit=…；支持 around message ID |
| 发送 | POST /api/chat/sessions/:id/runs，返回已持久化 message/run ID |
| 订阅/停止/重试 | GET /api/chat/runs/:id/events?after=seq；POST /:id/cancel；POST /:id/retry |
| 上传/预览/下载 | POST /api/chat/sessions/:id/attachments；GET /api/chat/attachments/:id/content |
| 登记产物 | POST /api/chat/runs/:id/artifacts，由通用工具调用 |
| 导出 | GET /api/chat/sessions/:id/export?format=markdown |
```

复用既有 auth 与参数校验，不新增 stage/Task 权限系统。选项引用、文件大小、状态、幂等属运行硬边界；业务判断交给 Agent。所有列表有分页，错误带可读说明，未知 Agent ID/失效 session 明确报错。

旧 POST /api/chat 在新前后端同时切换后移除，不维护两条会话执行链路。现有 gzip 排除需覆盖新事件订阅路径，反向代理也检查缓冲与超时；普通 JSON 请求仍可压缩。统一 UI API 类型、router 与本地工具参数。

## 10. Prompt 和 Jarvis 的关系

当前 Chat 是交互阶段，不是 M3，不把每句话经 M2→M3 再建 Task。用户直接对话可即时查询、使用工具处理请求；确需等待/脱离会话持续执行的工作，由 Agent 调用现有 Task 创建入口。代码不按关键词“帮我做”或 action_type 分类分流。

推荐最终有效输入：

```text
已注册 chat-system-prompt.md（Chat 身份、职责、停止条件）
+ StageChat 的工具目录（能力与命令真源）
+ 按仓库实际 Skill 发现机制提供的 Skill 目录/所需正文
+ shared memory（只含行为偏好，限于 Chat 职责）
+ 本轮 live conversation context（既有 contextsnap）
+ 显式来源与页面选择的冻结说明、附件清单
+ 原生会话历史或跨 Agent 完整可见历史索引
+ 当前用户消息
```

`systemGuidance()` 正文迁入 `conf/prompts/chat-system-prompt.md`，在 textstore 注册并使用 identity 装饰器。不能留下 Go fallback。职责规范以 Chat 文件为唯一真源，不注入 m3.md / m5.md 再“忽略不适用部分”。原生 CLI 还可能自动读取 AGENTS.md/Skills；适配器契约测试必须记录最终工作目录与自动加载机制，不能仅核对 Jarvis 拼接字符串就声称完整输入一致。

首轮注入角色/工具/记忆，续轮传最新现场与用户消息。若稳定配置文件版本变化，下一轮显式刷新相关指引并留版本记录；不反复注入完整历史。已有原生 session 无法替换早期指引时提示新建会话，不能在后台重写旧输入。

长任务交接在创建时冻结会话引用、用户原文、附件与当时背景到既有 source_payload；后续当前目标与进展归 M5。对话显示真实 Task 卡、状态和跳转，绑定由创建工具实际返回的 Task ID 产生，不能从回复文字猜。首次创建复用幂等提交方式，避免重试生出两份后台工作。

Chat 直接产生的外部动作由 run effects 留痕；Task 动作仍在 ExecutionRun.effects，不复制制造双重计数。涉及具体外部副作用是否询问由 Agent 结合用户授权和当前审批策略判断，不增加固定 propose/apply 阶段。若需要把 M5 的审批尺度复用于 Chat，应在实施时确认共享策略的语义所有权，不能直接挪用整套 M5 输出协议。

Chat 历史不自动变成 shared memory，不把全部闲聊灌入事实引擎。Agent 需要沉淀明确事实时复用既有世界模型工具；后台事实流水线的来源扩展作为单独需求处理。

## 11. 实施顺序与验收

推荐完整交付，按三个闭环实施，避免中途半套页面对外声称已完成。

1. **持久会话 + 第一 Tab**：导航/深链、会话列表与搜索、草稿、服务端消息/run/event、可靠停止/断线恢复、Markdown、导出。先复用已在运行的 Agent 协议。
2. **三个 Agent + 动态模型**：探测、适配器契约、每会话配置、5 项+全部、能力驱动、跨 Agent 携带记录新建。聊天默认值与后台配置分开。
3. **资料与附件闭环**：来源面板、从任务/世界跳转带上下文、上传/粘贴/预览/下载、产物登记、移动端与异常状态，串联真实 Task 结果。

改动范围：`web/src/App.tsx`、pageContext、Chat 与独立 session/composer/message 组件、chat 样式、api/types；`internal/chat` 的 service/store/run/adapter；domain/store 迁移；API/router/main wiring；textstore/prompts/toolcatalog；必要架构与接口文档。复用已有 Markdown、页面上下文、身份、世界模型、Task Submitter；不改 M2/M3 准入。

| 验收用例 | 必须成立 |
| --- | --- |
| 首页与深链 | 空 hash 首先看到对话；原任务链接仍打开任务；移动端第一项一致 |
| 多会话 | A 生成时进入 B；A 回复不进入 B；刷新两边历史与草稿可读 |
| 实际模型 | 每个 Agent 至少一轮新建+续聊+选另一模型；执行记录与选择一致 |
| 动态目录 | 目录从 6 项变 7 项无需改前端；0 项/失败/失效选择无假选项 |
| 编码与输入 | 中文输入法 Enter 不误发；Shift+Enter 换行；较长消息完整保留 |
| 停止与恢复 | 停止发往服务端；断线重连不重跑；终态先落盘再显示；重启中断可见 |
| 事件流 | delta+completed 不重复；工具事件有显示；SSE 分块/多行/尾块正确解析 |
| 幂等与部分失败 | 双击一轮；run 创建/启动/写事件中断可诊断；不使用 DB 事务 |
| 视觉附件 | 图片首轮/续轮真实被模型识别；纯文本模型不会静默丢图片 |
| 文件闭环 | 原件下载字节一致；生成产物登记后可下载；文件缺失明确报错 |
| 来源 | 从任务进入时保留原选项；新会话不串来源；失败引用不伪装空事实 |
| 切 Agent | 原 session 不变；新 session 含可见历史；不把原生 thread ID 跨源复用 |
| 布局与无障碍 | 1440/1024/390px 无横向溢出；按钮有名字；弹层可键盘操作/关闭；不抢滚动 |

适当验证包括 Go store/run/adapter 契约测试、前端现有 typecheck/build 与浏览器关键交互；真实三种 CLI 的模型调用需在实现后执行并记录，当前只做了只读发现，不声称真实回复验收已通过。构建或重启主服务一律走 `./scripts/rebuild-server.sh`。

## 12. 待评审决定

推荐接受“持久会话运行时 + 三个薄适配器 + 现有世界上下文 + 本地附件”的完整方案。复杂性来自跨页面持续生成、历史真源、三种原生会话协议与附件生命周期，不能仅移动按钮完成。

更简单的替代是先只做第一 Tab 和单 Agent 会话，之后补另外两种 Agent/附件；它能降低首批改动，但属于本次需求的部分交付。是否分批上线由用户决定，不能把第一批完成等同于全部完成。
