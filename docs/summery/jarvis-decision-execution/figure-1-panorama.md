# 图 1 · Agent 决策与执行全景

成品：`panorama.png`（4:3）

## 这张图要说的一句话

判断可以重来，动作不能。决策侧刻意容错，执行侧刻意不容错。

## 结构

图分四层，从上到下读。

**左列**是入口：数据源列出线索从哪来，触发列出什么时候开始想。M2 采集只存原文不判断，主动巡视绕开前半段直接建 Task。

**上带「判断依据（注入）」**是喂给模型的东西，分四组：世界上下文（冻结快照 + 实时 current_world）、规则（系统提示词 / 工作规则 / 审批策略）、记忆（共享记忆 / 长期事实页 / 跨轮进展）、能力（工具目录 / Skill 目录）。两条橙色虚线箭头标出它注入的位置只有快脑和慢脑两处。

**中带「决策与执行内核」**是主链，宽窄交替：快脑 M3 判"值不值得想"，固化不调模型只做机械搬运，慢脑 M5 判"该怎么做"，审批是可以随时停下的一步，执行只发生一次。慢脑下面挂只读子 agent，翻素材只回结论、不得再派生。右侧终态列出六种合法结局。

**每张卡底部的绿色页脚条**是这一段的机器边界，颜色由浅入深，配合下方"约束强度"箭头，表达越往右约束越紧：从幂等身份、会话水位，到事务加唯一索引、状态抢占，最后到 append-only 的事件流。

**底部回写带**收口：快路径把 run 和 progress_summary 送回下一轮 current_world，慢路径把 task_event 经 FactEngine 沉淀进世界模型。右侧回环箭头连回上带，表示这是个闭环。

## 概念框架

M3 = 快脑，M5 = 慢脑，与飞书文档第二章的两个 h2 一致。

（注：本目录另有一套 `01`–`05` 的图采用不同框架，认为"M3 只是低成本准入，快慢脑都在 M5 内部"。两者不兼容，当前采用前者。）

## 制作方式

image gen 生成，4:3。迭代要点：

- 六道闸做成**卡片底部的页脚条**而不是独立一条带，对齐由结构保证，不依赖模型听指令。此前用独立带做了三版，每版都错位一格。
- 需要修改时**用完整规格重新生成**，不要用"照抄参考图 + 只改 N 处"的模式。后者会连带重写文字，实测一次改出六七处错别字（"冻结快照"→"系统快照"、"拿不准就放行"→"富不虚做胶行"）。
- 窄条要留够宽度，否则 `exactly-once` 这类标签会折行。

若后续需要精确到像素或频繁改文案，改用手写 SVG（本目录 `01`–`05` 已有 SVG + PNG 双份的先例）。
