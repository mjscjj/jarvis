# Jarvis 主动程度三档设计

状态：三档规则、配置、设置页与运行时组装已实现（2026-09-10）。本文保留设计依据，实际行为真源为当前 prompts、rules 与代码；本次验证与服务启用状态见末节。

## 1. 产品目标与确定的选择

在「工作设定」顶部提供一个全局设置：**主动程度：安静 / 普通 / 活跃**，默认普通。

这个选择同时影响三个判断：哪些线索值得启动执行、执行时是否扩展相关工作、哪些结果值得占用 Principal 的注意力。三个判断由对应 Agent 结合上下文完成，代码只传递当前选择。

| 档位 | 设置页说明 | 用户应感受到的变化 |
| --- | --- | --- |
| 安静 | 优先处理明确交办和确定需要介入的事，减少主动建议。 | 模糊反馈少建任务，后台调查少播报，重要交付仍送达。 |
| 普通 | 按当前方式发现、处理和通知。 | 与改造前相同的准入、调查、回顾和回执尺度。 |
| 活跃 | 更主动发现相关机会、提前准备，并提供可行动的建议。 | 在用户开口前多完成一些有依据的准备，收到更多有用建议。 |

只有一个全局档位，不拆成多个滑杆，不增加按项目、群或来源配置的覆盖层。采集频率、模型、工具和调度并发维持现有设置。2026-09-11 按 Principal 确认更新下述审批尺度与 Bot 单聊方式。

“安静”不要求调查结论预先确定：需要确定的是**有一件与 Principal 有关、现在值得处理的事**。原因未知、方案未定或负责人信息不全，可以由 M5 查明。例如“帮我查登录超时”在三档都直接准入。

## 2. 当前有效链路与打扰来源

当前真源以代码及配置为准，旧设计文章中的审批状态与消息协议不作为实施依据。

| 位置 | 当前行为 | 对设计的约束 |
| --- | --- | --- |
| `conf/prompts/m3-system-prompt.md` | Principal 直接交办、leader 软性要求直接准入；拿不准就 extracted；observing 只用于明确无需推进。 | 当前普通档已偏积极；安静档必须调整这些语义的适用范围。 |
| `conf/rules/m3.md` | 每个独立用户问题、负面体验、功能诉求、待验证修复均准入；实际参加且缺回顾的会议生成回顾任务。 | 不能保留为所有档位的无条件例外。 |
| `internal/extract/worker.go`、`prompt.go` | 读取系统提示词、M3 rules、共享记忆、Skills、工具目录，加入消息和背景；一次批次可生成多个 conversation unit prompt。 | 档位必须在这条组装链路生效，两种提取引擎共用。 |
| `internal/execute/materializer.go` | extracted Todo 机械固化成 Task。 | 固化层继续只消费状态，不增加档位判断。 |
| `conf/prompts/m5-system-prompt.md`、`conf/rules/m5.md` | M5 核验、执行、适度扩展；存在主动增益、送达有用结论和真实对外动作回执要求。 | 通知尺度与扩展尺度归 M5 rules；实际消息由 M5 调工具发送。 |
| `internal/execute/agent_executor.go`、`prompt.go` | 初次执行、等待恢复、人工回答恢复都组装当时的 M5 指令；恢复继续原 Session。 | 三条入口都应读取当前档位，不能只改初次执行。 |
| `conf/prompts/proactive-system-prompt.md`、`internal/proactive/worker.go` | 主动巡视直接创建普通 Task，不经过 M3；当前默认每轮新建 0–1 个，紧急独立事项最多 3 个。 | 巡视接入同一个档位；保持当前预算和停止边界。 |
| `internal/skill/skill.go` | 启用的 Skill 可以内联正文进入有效输入。 | 同时核对领域 Skill，避免它们继续无条件要求准入或通知。 |
| `internal/agentconfig/service.go`、`web/src/AgentSettings.tsx` | 已有工作设定、文本读写和 M3/M5 生效预览。 | 复用现有配置与预览，不新增一套设置服务。 |

普通消息、问题卡和处理 reaction 是三种不同的触达：

- 普通消息由 M5 决定并执行；这是通知档位的主要作用点。
- 问题卡由 M5 返回 `needs_human + question` 后，runtime 持久化并投递。档位影响是否值得提出可选问题，不在发送层丢弃已产生的问题卡。
- `OnIt` reaction 是现有执行生命周期的机械反馈，第一版维持原有添加与清理，不按档位再开分支。安静档不是完全免打扰模式。

## 3. 所有档位共同履行的工作

### 3.1 明确交办、已接受承诺和订阅

Principal 明确要求 Jarvis 完成的工作，三档都处理，必要调查深度、完成标准和结果交付不降低。

Principal 明确订阅的固定产物与看护工作继续履行。例如“每天给我发晨报”“每场会后都给我总结”“持续核验这条交办”，已有启用配置和真实指令构成判断证据。固定产物的投递仍由其已有任务或 Skill 完成，不因切档增加第二份通知。

需要区分：

- 启用一个采集来源或提供一种 Skill 能力，不自动等于要求每条线索建 Task、发通知。
- 启用一个明确约定定期交付或持续跟踪的功能，按其公开目标履约；额外的主动扩展仍服从当前档位。
- 仓库默认的“每场会议回顾”属于可随档位变化的预置行为，不能因写在 rules 中就被当作用户单独订阅。反馈按通用准入口径判断，不再保留“每条负面反馈跟踪”特例。

这些由模型依据已提供的配置、原始指示和目标判断，不新增 `explicit_request`、`is_subscription`、来源豁免等贯穿全链路的硬字段。

### 3.2 不因档位降低事实与交付要求

三档都需要原始证据、准确去重和真实结果。活跃档可以根据有依据的推断发起调查，不能把推断写成事实；安静档可以不接一个可选机会，不能把未完成事项标成完成。

真实代表 Principal 对外执行的动作，仍按现有回执规则确保 Principal 知道；已在其参与的话题中真实送达，不追加相同私聊。安静档的减噪主要来自少接可选工作、少扩展、少播报纯调查过程，不靠隐藏已发生的动作。

审批尺度只由 `conf/prompts/m5-approval-policy.md` 维护：安静档触达其他人需审批；普通、活跃档先检查已有授权，不重复请示。目的、对象、内容明确的消息，普通档确认无风险、活跃档判断为低风险时，可直接群发或 Bot 单聊并 CC Principal；群内真实 @，单聊或 Principal 不在群内时同步收件人和实际正文。消息授权不包含其它修改操作，Skill 不再强制个人消息走助手群。

## 4. M3：准入三档

M3 保持最短准入判断，不增加分析阶段，也不为了符合安静档先把事情查完。

| 判断对象 | 安静 | 普通 | 活跃 |
| --- | --- | --- | --- |
| Principal 明确交办 Jarvis | extracted | 保留现状 | extracted |
| Leader 的软性表达 | 能确认具体期望结果和 Principal 责任时 extracted；纯泛化建议先观察。 | 保留软性要求直接 extracted。 | 保留直接准入，并可识别有证据的准备需求。 |
| 与职责相关的未闭环事项 | 有明确待完成结果、确需介入或已有明确看护要求时 extracted。 | 保留现有未闭环口径。 | 同普通，并纳入可说明实际收益的前置准备。 |
| 模糊反馈、泛化建议 | 未达介入标准时 observing；既不值得保留也无需行动则不输出。 | 按通用准入判断相关性、未闭环结果与介入需要。 | 可启动有明确调查目标的 Task，避免把每种措辞拆成新任务。 |
| 他人已认领且正常推进 | 没有 Principal 的额外责任、明确跟踪要求或具体风险时 observing。 | 口头认领不等于闭环，是否需要跟踪按通用准入口径判断。 | 可核验对 Principal 有影响的依赖，不自动接管他人的交付。 |
| 缺会后回顾 | 有明确总结要求，或已有事实说明回顾服务具体决策、承诺时 extracted；仅“参加过”不够。 | 保留实际参加且缺回顾即准入。 | 保留回顾，并识别有证据的准备或独立后续事项。 |
| 未来会议 | 已确认承担汇报、决策或准备职责，且存在材料缺口时 extracted。 | 保留当前日历规则。 | 有证据表明准备会带来收益时更早准入，交 M5 选时机。 |

### 状态含义调整

M3 的 `observing` 统一表述为：**值得保留，但按当前证据与本档标准，暂不启动 M5。** 它不表示事项完成，也不保证以后一定不需要处理。

“明确不需要推进”仍是普通档和活跃档的既有判断场景；安静档额外允许“尚无充分介入依据”。理由使用现有宽松 `payload / annotation` 说明，不增加原因枚举。

后续有新证据时，由 M3 对同一事项重新判断；没有新消息但出现临期、失速等变化时，由主动巡视在已有职责内判断。保持原始引用和去重，不因一次 observing 丢弃未来机会，也不因切档批量重放历史消息。

### 建议写入 M3 rules 的核心正文

> 安静档：优先处理 Principal 明确交办、明确承诺及有证据表明必须介入的未闭环结果。区分“需要处理是否明确”和“执行细节是否齐全”；前者明确即可准入，后者交 M5 查明。只有可能相关、可能有用，而无法说明现在为什么需要介入的，保留观察，不为补齐准入条件扩大调查。
>
> 普通档：沿用当前准入尺度，包括 Principal 直接交办、leader 软性要求、未闭环事项、不确定时交 M5，以及本档领域规则。
>
> 活跃档：沿用普通档，并识别有具体证据支持、与 Principal 当前目标有关的前置准备和改进机会。准入说明应能交代机会是什么、为什么现在值得处理、预期帮助形成什么结果；这些是自然语言判断要点，不是新的必填 schema。无关猜测、同义重复和为了活跃而制造任务都不准入。

M3 系统提示词只保留任务准入职责、状态和输出协议、调查停止边界；将当前散落的“拿不准直接 extracted”等尺度迁入本阶段 rules，不在旧指令后追加“安静档忽略以上要求”。

## 5. M5：执行范围、通知和提问

### 5.1 工作做到哪里

| 档位 | 必要工作 | 相关扩展 | 停止方式 |
| --- | --- | --- | --- |
| 安静 | 把明确目标做完，充分查证阻塞和结论。 | 仅处理对原目标不可缺少的依赖；可选发现留在 Task。 | 达到原目标后收口，不为可选建议再开审批或跟进。 |
| 普通 | 保留现有多路径调查、持续重规划和完成标准。 | 保留当前低成本主动增益。 | 保留当前停止规则。 |
| 活跃 | 完成原目标。 | 主动准备直接相关的选项、材料、风险说明；独立目标先核对是否已有任务。 | 有具体产物或已无决定性信息缺口即停，不递归扩大工作。 |

三档均不要求 M5 对每个 Task 从头重复 M3 的泛化准入评估。Task 是已经接下来的工作；M5 根据真实证据调整目标、当前范围和下一步。

### 5.2 什么值得通知

以下分类只是帮助模型判断，继续使用现有消息与 `question` 机制，不变成程序枚举。

| 信息 | 安静 | 普通 | 活跃 |
| --- | --- | --- | --- |
| 明确交办的最终结果 | 按约定送达 | 同左 | 同左 |
| 已代表 Principal 真实对外执行的结果 | 合并回执，避免双重送达 | 保留现状 | 合并回执，不逐步播报 |
| 只有 Principal 能完成的决定或操作，且阻塞必要目标 | 按现有 question 提问 | 同左 | 同左 |
| 已确认、与其责任直接相关且有时效的风险 | 通知具体事实、影响和必要下一步 | 保留现状 | 可更早告知有证据的风险苗头，明确推断与不确定性 |
| 只读调查得到的一般进展、暂无需行动 | 默认留 Task | 保留现有信息价值判断 | 有明确决策价值或准备价值时通知 |
| 顺手发现的优化机会 | 默认留 Task | 保留当前低成本主动增益 | 给出有证据、能行动的建议，尽量附已准备好的材料 |
| 等待、重试、内部报错、没有新变化 | 默认静默 | 保留现有不按状态播报原则 | 不因活跃而重复播报 |

同一事项本轮多个动作与结论尽量合并成一次通知；跨轮复用历史 Task、effects 和原线程判断是否已经送达。新通知应带来会改变判断或下一步的实质信息。第一版不新增消息队列、固定每日条数或跨 Task 摘要服务。

### 5.3 避免“少发消息、多发问题卡”

面对可选机会，M5 先按当前档位判断是否值得现在推进；值得推进且下一步需要授权时，再按原审批策略提出具体问题。不要先把一个低价值想法扩写成对外动作，然后以“必须审批”为理由打扰 Principal。

例如安静档里调查发现“可以顺便向三个同事征集建议”，如果与原目标无必要关系，就把发现留在 Task，不创建三张请示卡。原目标确实依赖某人的回答时，仍按现有策略提出一个最影响下一步的问题。

runtime 一旦持久化了 `needs_human`，照常投递问题卡；消息工具不读取档位来拒发。这样责任始终落在发起行为的 M5。

### 5.4 与已有规则一起改

- 将 `conf/rules/m5.md` 中“有用分析必须送达”“主动增益”“默认不打扰但漏报更严重”等尺度组织到各档明确适用的段落，保留普通档原意。
- 真实对外动作回执、送达验证、去重、消息渠道和格式保留为共同规则。
- 会后回顾规则负责“接到回顾任务后如何做好”，不重新强制所有档位为所有会议建立回顾目标。
- M5 系统提示词中的任务扩展和日历通知措辞指向本阶段尺度；调查职责、完成判据、输出协议和审批策略保持各自所有权。

## 6. 主动巡视、插件与入口范围

主动巡视继续先看护已有工作，再看新变化，保持当前每轮预算和停止条件。

- **安静**：重点处理明确承诺、确定的时间风险和必要维护。没有新证据、没有到检查时机、已有负责人正常推进时，不为保险起见安排额外核验。
- **普通**：保留现有行为，包括时机判断、跨日看护和有证据的新任务。
- **活跃**：在相同预算内，更积极关联已有事实，发现会前准备、依赖风险、可复用成果和有时效机会。优先选最有价值的事项，不提高硬上限。

相关 Skill 只维护领域步骤和领域完成标准。特别检查 `my-delegations-extract` 的“尚需核验就 extracted”和 `my-delegations-review` 的检查时机：记录 Principal 已明确交给他人的待办继续保留，是否现在安排一次核验要结合明确看护目标、证据和本阶段档位；普通档沿用原行为。不要将三档正文分别复制进每个 Skill。

M2、会议采集、factengine 不减少证据采集与事实沉淀。安静档少执行不应导致背景信息质量下降。

手工、定时和其他直接创建的 Task 统一进入带档位的 M5。是否为明确订阅由真实目标判断，不按 `source_type` 在 Go 中分流。晨报等已有独立交付入口按原订阅运行。

CC Connect 接受的私聊 / @ 交互仍由原生会话处理，不在这次改造中改路由或延迟用户的直接对话。因此页面明确说明本设置作用于**后台主动发现、执行扩展和通知**，不宣称接管所有聊天回复。

## 7. 配置、组装与切档

### 7.1 一个文件保存当前选择

复用现有 `textstore`：

- 稳定 key：`initiative_level`。
- 文件：`conf/prompts/initiative-level.md`，它只保存行为策略的当前选择，不承载跨阶段规则正文。
- 文件内容：单独一行 `quiet`、`normal` 或 `active`。仓库提交值为 `normal`。
- 在 `internal/textstore/defaults.go` 注册，展示名“主动程度”，使用独立的配置 kind，避免进入“其他 Agent 提示词”编辑列表。
- 沿用 `GET/PUT /api/text-files/initiative_level`，写入体如 `{"content":"quiet"}`。
- 读取与写入都校验三个合法值，缺文件、空值、未知值直接报错，不悄悄回落普通档；写入继续使用现有原子文件替换。

固定三个值是设置控件与 prompt 组装共同消费的机器选择，不是对 Agent 理由、风险或业务判断增加枚举。当前选择不再同时写到 runtime YAML 或共享记忆。

共享记忆仍可以保存“某个项目的重要变化总是告诉我”等个性化要求；其范围应按原始用户意图理解，不把这些偏好升级成另一份全局档位。此次实施不批量重写用户的共享记忆。

### 7.2 最终有效输入

组装时加入一个机械标识块，例如：

```text
BEGIN_INITIATIVE_LEVEL
quiet
END_INITIATIVE_LEVEL
```

模式标识本身没有行为正文；各阶段提示词说明该值选择本阶段规则中对应的行为尺度。

```mermaid
flowchart LR
    UI[工作设定：三档选择] --> FILE[initiative-level.md]
    FILE --> M3[M3：档位 + 系统提示词 + M3 rules]
    FILE --> M5[M5：档位 + 系统提示词 + M5 rules + 审批策略]
    FILE --> P[主动巡视：档位 + 自身系统提示词]
    M3 --> TODO[extracted Todo]
    TODO --> TASK[机械固化 Task]
    P --> TASK
    TASK --> M5
    M5 --> ACTION[工具动作 / 必要通知 / 问题]
```

M3/M5 的模式参数进入现有 `prompttemplate.Render` 共同组装路径，生效预览调用同一实现。主动巡视使用相同的模式标识渲染函数，接自己的系统提示词，不读取 M3/M5 工作规则。

第一版三档尺度均留在对应阶段的同一份 Markdown 中，由当前值选择适用段落。不要复制三套完整系统提示词，也不实现 Markdown 条件解析器。所有通用和领域条款都写清范围，不能靠后出现的段落覆盖前面的错误指令。

完整输入仍包含原有共享记忆、Skill 目录或内联正文、工具目录、业务上下文和输出协议。模式放在运行时指令区，不塞入 `Task.source_payload` 作为永久执行约束。

### 7.3 生效时机

| 情况 | 建议行为 |
| --- | --- |
| 点击保存 | 文件写入成功后显示当前选择，无需服务重启。 |
| 已组装的 M3 批次 | 批次内各 unit 和格式重试沿用同一模式，下一批读取新值。 |
| 正在执行的 M5 / 巡视 | 本轮沿用开始时已组装的模式，不中断，不追加临时消息。 |
| 新 M5 执行、rerun、等待恢复、人工回答恢复 | 组装时重新读取模式；恢复继续原 Session，携带当轮值。 |
| 历史 Session 中存在旧模式 | 阶段系统提示词明确当轮标识是本轮选择，历史标识只说明当时行为；既有授权和交付证据继续有效。 |
| 已建 Task | 不删除、不批量降级、不重新经过 M3；下一轮按新尺度控制可选扩展和通知，继续履行明确目标。 |
| 已发问题卡 | 不撤回、不重复发送，不因切档解释为批准或取消；等待原问题回答。 |
| 已 observing 的线索 | 不因切档全量激活；有新证据或进入现有巡视候选时再判断。 |

例如活跃档刚准入一个准备任务，随后切安静档，M5 仍处理这条已经接下的工作，但不继续扩展和播报一般发现。想取消某条任务，使用现有任务操作；档位选择不兼任批量取消。

### 7.4 后台交互与留痕

在 `AgentSettings.tsx` 的阶段 Tabs 上方放三个单选项，并展示所选档位说明。选择后保存，保存中禁用重复提交；保存失败显示原有效值和错误，避免界面假装已经切换。

辅助说明：“作用于后台主动发现和通知。明确交办与订阅继续执行；正在处理的工作从下一轮采用新设置。”

保存后刷新 M3/M5 生效预览。预览包含当时读到的真实模式，不在前端拼接一份模拟规则。若预览刷新失败，要区分“档位已保存”与“预览加载失败”。

M5 与 proactive 已有持久化 Prompt，直接保留所用模式，不新增 Task 档位列和配置历史表。M3 验收导出实际 System/User 输入留作对照；实施时核对现有调用日志的留存能力，不假设已经具备永久的 M3 完整输入档案。模型的准入或停止理由继续写现有自然语言字段。

## 9. 验收样例与验证方法

### 9.1 行为对照样例

| 输入与现场事实 | 安静期望 | 普通期望 | 活跃期望 |
| --- | --- | --- | --- |
| Principal：“帮我查登录超时”，原因不明。 | 建 Task 并查明，按约定交付。 | 同左。 | 同左，可补直接相关的预防建议。 |
| Leader：“以后这个方向可以关注一下”，无具体交付。 | 观察，不立即追问。 | 保留软性要求准入。 | 可识别有依据的准备方向。 |
| 用户泛泛说体验一般，无直接交办。 | 观察；无需行动也无记忆价值则不输出。 | 按通用准入口径判断，不因反馈来源自动建任务。 | 结合证据调查，形成有用改进材料。 |
| 同事已认领普通问题，无明确看护要求或风险。 | 观察，不替 Principal 公开追问。 | 保留当前规则，M5 决定是否继续。 | 可核验关键依赖，不自动催办。 |
| 实际参加一场例会，无行动项、无明确总结订阅。 | 不仅因参加而建回顾 Task。 | 缺回顾则建 Task。 | 缺回顾则建 Task，有证据再提取后续机会。 |
| Principal 明确要求“每场会后给我回顾”。 | 按订阅回顾和投递。 | 同左。 | 同左，额外发现按本档尺度判断。 |
| 明天负责评审，材料确有缺口。 | 建必要准备任务。 | 保留现有会前规则。 | 提前准备材料和决策选项。 |
| 只读调查证实他人已处理，无需介入。 | Task 留结论，不额外通知。 | 按原有信息价值判断。 | 无实质新增价值也保持安静。 |
| 核实 Principal 承诺的交付将错过明确期限。 | 通知事实和影响。 | 同左。 | 可更早识别和准备应对选项。 |
| 有一个与原目标无必要关系的建议，需要向群发消息。 | 留发现，不为此开问题卡；触达他人需审批。 | 值得现在做且明确无风险时直接发送并 CC；否则按审批策略处理。 | 值得现在做且明确、清晰、低风险时直接发送并 CC；否则按审批策略处理。 |
| 本轮已经在原话题真实 @ Principal 交付结果。 | 不重复私聊。 | 同左。 | 同左。 |
| 等待恢复前 active 改为 quiet。 | 原目标继续，恢复带 quiet，减少可选扩展和播报。 | 不适用。 | 不应继续沿用旧 active 作为当前设置。 |
| 人工问题尚未回答时切档。 | 保留原卡片与状态，不代答、不重发。 | 同左。 | 同左。 |
| quiet 观察的旧线索后来出现明确交办。 | 更新同一事项并准入，保持去重。 | 按当前规则。 | 按当前规则。 |

### 9.2 工程验证

- 配置：三种合法值均可写入读回；未知 key、空值、非法值、缺失文件 fail-fast；写入立即对后续读取生效。
- 组装：M3、M5 初次执行、两类恢复、proactive 与预览均带实际模式；各受影响阶段没有遗漏入口。M3 批次重试保持同一模式。
- 边界：档位仍不参与固化、消息投递和审批状态分流；Task 来源快照保持原始证据。
- 页面：真实后端读回作为保存结果；写入失败和预览失败分别展示；不出现第二个模式文本编辑入口。
- 文案审阅：逐项对照当前规则，普通档不遗漏原有准入特例、会议回顾、主动增益和回执；安静档没有仍无条件生效的相反指令。

复用现有 Go 测试位置增加必要契约覆盖，运行受影响包测试和前端类型检查/构建。只改设计文档时不运行服务或行为评测。

### 9.3 行为评测

选取约 15–20 个真实片段，补充上表中的边界样例。固定世界模型背景、现有 Task、模型与工具证据，用三档分别评测；普通档另与改造前输入对照。

不把只包含“模式字符串”的单测当作模型行为证明。M3 对比候选与理由；M5 对比实际选取的动作、消息文案与 question。评测使用隔离任务数据和捕获写入意图的测试工具，避免向真实收件人发消息或污染生产待办。完成真实集成验证时再沿用项目已有受控测试方式。

记录建 Task 数、有效结果、通知数、问题卡数、明确交办漏接、重复动作、错误事实与越出目标的扩展。计数从具体结果和动作证据汇总，不能只数 completed。

验收重点：

1. 固定样例内，明确交办与明确订阅没有因档位被漏掉；三档的事实要求一致，授权要求按当前审批策略判断。
2. 安静档在模糊线索上更少启动任务，在一般调查上更少通知，也不转化成更多无必要的问题卡。
3. 普通档的规则范围与改造前一致；对模型输出差异逐例核对，不承诺随机模型逐字一致。
4. 活跃档至少在有证据的机会样例中产生新增的具体准备或建议；单纯多建任务、多通知不算成功。
5. 恢复时确实使用新档位，历史指令、授权、已发生动作和未闭环目标没有丢失。

这里不预设“必须减少 50% 消息”等无基线指标；先用样例校准，再根据真实使用反馈收紧各档正文。档位是模型判断尺度，第一版不承诺消息数量的硬上限。
