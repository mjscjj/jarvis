# Todo / Task 证据分层与 M5 渐进加载方案

> 2026-09-05；设计方案，未实施。
> 本文按用户最新明确的边界重写，替换此前合并 Todo/Task 的错误方案。
> 范围只有两项：Todo/Task 的宽松分层内容结构，以及 M5 的上下文加载机制。
> Todo 仍是高噪声线索；Task 仍是已经进入执行、有明确成本和目标的任务。M3、固化、M5 的定位与状态职责保持。

## 1. 设计结论

保留两类对象，只统一它们描述证据的方式：

**事项摘要 → 直接触发原文 → 发生现场 → 延伸背景。**

M5 默认读取当前任务摘要、直接触发原文和简短现场；更广背景、其他 Todo/Task 及执行历史按需查询。

分层是“这条材料对当前事项起什么作用”，不是按消息、群、人物、项目类型机械分类，也不是四种业务状态。一个项目的截止时间如果直接触发行动，就可以属于一级证据；一场会议的完整历史则可能只是延伸背景。

## 2. 四层内容及默认加载方式

| 层 | 回答的问题 | 典型内容 | M5 默认加载 |
| --- | --- | --- | --- |
| 摘要 | 这是什么事？目前到哪？ | Todo 的线索概述/不确定性；Task 的当前目标、进展、剩余事项 | 当前对象完整短摘要 |
| 一级：trigger | 究竟是什么原文或事件触发了它？ | 直接交办消息、被指代的链接、邮件请求段落、原始事件和定时交办指令 | 必要原文、作者/时间/出处 |
| 二级：scene | 当时谁在什么场合讨论什么？ | 本次对话或事件的现场、直接参与者身份、群/线程用途、必要前后关系 | 简短现场描述及相关材料入口 |
| 三级：background | 为进一步判断还能查哪些背景？ | 项目摘要、人物/群长期事实页、相关资料、历史事项和更广对话 | 摘要式目录，不展开全文 |

层级不是可信度等级。用户原话、他人表述、模型推断仍标明各自来源。现场叙述是模型整理时要明确是整理，不能替代引用原文。

### 例子：review“这个代码”

- 摘要：principal 要求 review 指定 MR。
- trigger：上一条完整 MR 链接 + “jarvis 你来仔细 review 下这个代码”这句原话，附各自来源。两条共同构成可理解的触发，不能只给“这个代码”。
- scene：谁分享了 MR、谁交办、在哪个讨论现场；此前是在求 approve，还是在讨论某个问题。
- background：项目摘要、相关人员职责、更长线程和历史 review 记录的入口。

不是“最新一条消息=一级、之前所有消息=二级”，也不是“固定最近 25 条就是现场”。由 M3 在准入所需范围内选证据，M5 在执行时按需要继续展开。

长邮件、会议、工单使用同样原则。一级保存准确原始出处及必要原文；原文很长时可引用准确段落并注明全文未展开。完整材料必须可达，不在采集或交接时截断。

## 3. 存储：薄控制字段 + 一份宽松分层内容

### Todo

保留 ID、状态、版本、来源关联，以及确实用于去重、过滤、排序和固化的字段。完整语义保存为一个 `content JSON`，承担原来分散的线索描述、准入理解和背景。

Todo.content 的摘要描述“观察到什么、为什么值得保留、哪里不确定”；不写成已接受执行的承诺。它随线索新证据形成新修订，继续使用原有 revision/version 语义。

### Task

保留 ID、todo_id/其他来源关联、状态、版本、调度和执行所需字段。

- `source_payload JSON`：创建 Task 时冻结的完整分层来源内容。Todo 来源复制当次 Todo.content；其它来源提供同样的内容组织。它是原始依据，不在 M5 修改。
- `summary TEXT`：M5 维护的当前目标、进展、剩余事项。与冻结来源中的“当时如何理解”分开。
- 人工补充、Run、effects、TaskEvent：沿用各自职责，保留真实指示和执行留痕。

不再让 `Task.source_payload` 和 `Task.background` 分别装两套需要一起解读、部分重复的背景；分层原始依据集中在 source_payload，当前进展仍在 summary。

这里明确保留 Todo→Task 固化。同一份 JSON 在 Task 创建时冻结一份是合理的历史快照：Task 不能仅引用会继续更新的 Todo 当前值。本次不为消除磁盘复制再引入快照服务、引用计数或版本数据库。

### 内容示意

下面是推荐写法，不是限制模型的完整字段清单：

```json
{
  "brief": "principal 要求仔细 review 指定 MR，目前尚未执行。",
  "trigger": {
    "summary": "直接交办，代码对象由上一条链接明确。",
    "refs": ["mr_link_message", "request_message"]
  },
  "scene": {
    "summary": "同事在相关讨论中分享 MR，随后 principal 指名交办。",
    "refs": ["discussion_context", "requester_identity"]
  },
  "background": {
    "summary": "相关项目与人员职责可用于进一步核查。",
    "refs": ["project_context"]
  },
  "materials": {
    "mr_link_message": {
      "message_id": "om_link",
      "content": "https://example.com/repository/merge_requests/456"
    },
    "request_message": {
      "message_id": "om_request",
      "content": "jarvis 你来仔细 review 下这个代码"
    },
    "discussion_context": {
      "captured_at": "创建时刻",
      "description": "原始现场材料保存在这里；可包含会话、事件和材料引用。"
    },
    "requester_identity": {
      "description": "创建时已知的身份依据，保留其来源。"
    },
    "project_context": {
      "summary": "与本事项相关的项目背景。",
      "page_ref": "project:7",
      "captured_at": "创建时刻"
    }
  },
  "assessment": "M3 的准入判断、已核验内容和仍不确定之处。"
}
```

`materials` 只是该 JSON 内按 key 保存的原始材料，不是新的表、知识库或缓存。引用使同一消息/人物材料在内容中只需保存一次；不同层可以引用同一材料。模型可以为材料增加 URL、作者、时间、线程、外部对象 ID、备注等任何需要的内容。

完整捕获的上下文继续保存在材料中，即使当前默认视图不展示。原始抽取结果里的其它语义字段也保留，不经过固定 DTO 解码后丢弃。

**程序只固定少量读取协议：**层的名称、summary、refs，以及材料 key 的定位；材料正文、场景描述、准入判断等使用 json.RawMessage/自然语言。层可以为空，未知字段保留。层是内容读取边界，不增加业务语义枚举或强制人员/群/项目嵌套 schema。

仅校验 JSON、引用可解析、已有来源引用/原句能与采集记录对应等硬边界。不会要求必须有群、必须有项目、必须找全所有人物；缺少某层内容不触发补全调查。

## 4. 谁生成这些内容

- **采集和上下文装配代码**：保留原始材料及来源信息，提供可引用的材料 key。不能猜哪些消息重要，不能把错误解释成结论。
- **M3**：在准入判断中写 brief，选直接触发引用，概括足够理解交办的现场，并给出已知背景索引。做到能准入就停，不为填三级背景而深挖。
- **固化**：原样冻结分层内容到 Task.source_payload，不重新查询实体页、不改写摘要、不调用另一个模型压缩。
- **非 Todo 来源的创建者**：把原始交办放到 trigger，提供已有现场/背景。明确的定时或手工任务不为套格式强行经过 M3。
- **M5**：围绕真实目标按需读取、补充事实；当前理解写 Task.summary 和执行记录，保留冻结来源。

材料按作用分级是 prompt 中的判断要求；Go 只按模型给出的层和引用读取。不会出现 `if source == 群聊` 或 `if type == 人物` 来指定语义层级。

## 5. M5 默认输入与后续读取

默认业务输入为：

```text
当前 Task：目标/进展摘要、状态、有效人工补充
一级证据：原始交办和构成指代的必要原文，附作者/时间/出处
二级现场：短描述，以及群/事件/人物等直接关联的材料入口
三级背景：相关背景摘要与读取入口
历史：有无既有 run，查询已有结果和 effects 的入口
```

一级的原文优先级最高，但不等于把整个文档、整段线程都提升成默认输入。直接交办短文本可完整内联；长材料由 M3 给出准确摘录和全文入口，M5 必须在依赖未读部分作判断前展开。程序不按固定字符长度替模型截掉原始要求。

同一条原文只内联一次，不再同时出现在 messages 和 conversation 两份列表中。scene 与 background 默认只渲染描述及引用，不递归展开所指向的材料。

不再自动注入全局最近 20 Task + 20 Todo，也不默认重放本任务所有 run.output。当前 Task.summary 是当前进展；既有副作用保留在 Run/effects，需要续跑或决定是否重复行动时核查。

恢复同一 Session 时提供当前 Task 状态/summary、新的人工作答和时间；已读的冻结原文不用重复灌入，涉及当前事实时重新查询。

系统角色、M5 rules、审批策略和可信指示仍按原有作用域提供，不能用上下文压缩省略权限或任务完成约束。

## 6. 工具：现有 list/get 加两个明确的读取选择

以下是设计中的命令形态，尚未实现：

```text
list-todos --query '关键词或对象链接' --page 1 --limit 10
list-tasks --query '关键词或对象链接' --page 1 --limit 10

get-todo --id ID
get-task --id ID

get-task --id ID --context scene
get-task --id ID --material discussion_context
get-todo --id ID --material request_message
```

- list：短摘要、状态、来源引用和对象关联；不返回全文材料。
- get 默认：当前对象摘要、触发现场和下钻入口，与 M5 默认输入使用同一读取逻辑。
- `--context trigger|scene|background`：返回对应层的内容与材料目录。
- `--material KEY`：返回这一项完整原始材料，保留未知字段与出处；大材料可以重定向到文件再用 jq/文本工具读取。
- 实体当前状态继续走 get-page，具体来源/文档继续使用已有原子工具，运行结果使用现有运行记录入口。

这是一个层选择和一个材料 key 查询，不引入七八种 part、JSON Pointer API、跨对象 WorkView 或通用内容服务。可变 Todo 的读取返回 revision/version；依赖同一次快照时带预期版本，变化则重新读取，不能静默混用。Task 创建时依据始终冻结。

读取器只在 Todo.content 或 Task.source_payload 内解析材料 key，不把任意外部文本当作数据库列名或文件路径。完整内容可显式读取，默认未展开与不存在必须区分。

## 7. 其他 Todo/Task 怎样帮助防重

保持两种查询入口和两种业务语义。列表给出：

- 这是什么线索/任务；
- 来源证据、对象链接及已有 Todo→Task 关联；
- 线索状态，或执行进展与结果入口。

先搜索相关记录，再读触发证据和必要结果。可以按已有来源 ID 精确过滤，也可以按目标、对象链接和关键词检索；覆盖所有 Task 来源、所有状态，并支持真实分页。

搜索优先使用 brief/summary、触发引用和实际结果，不默认搜索整个宽泛背景。代码不生成一张全局相关性排行榜，不按标题或原文相同自动判重复。

同一证据可能产生多个任务，不同来源也可能描述同一工作。M5 判断目标、范围、版本及结果是否覆盖当前请求。failed 任务可能已有成功副作用，done 也不能代替结果核验。

原有 Todo 去重、准入与固化机制不因这次加载改造另行重做；查询和原文可达能力服务这些阶段，阶段职责不改变。

## 8. 当前代码的修改闭包

| 位置 | 修改 |
| --- | --- |
| domain / store | Todo 语义收敛为 content；Task 的冻结语义收敛到 source_payload，summary 表示当前进展；保留有实际消费者的控制/关联字段 |
| extract/candidate、persist、snapshot | 用小控制外壳保留完整原始 JSON；M3 输出分层描述和引用，原始材料原样固化，取消全链路人物/群/项目语义 DTO 约束 |
| execute/materializer、taskcreate | 保持原流程，改为复制同一份分层来源内容；非 Todo 创建使用相同协议，不加来源专用分支 |
| execute/prompt、agent_executor | 改成当前摘要 + trigger 原文 + scene 简述 + background 索引；初始/恢复按时态读取 |
| execute/currentworld、prior_runs | 删除全局 20+20 与完整历史输出的默认装载，改用查询入口和当前进展 |
| contextsnap | 收敛为小的分层读取/引用校验辅助代码，材料正文保持 RawMessage；不是新的上下文管理模块 |
| api / jarvis-tools | 列表搜索和分页；默认轻量 get；层读取和材料单项读取，避免查询一个任务自动展开整个档案 |
| prompts / toolcatalog / docs / tests | 同步分层语义、原文优先、按需下钻，以及“完整保存并可达，不等于全部内联”的交接契约 |

删除 description/context/open_questions 等冗余语义投影前核对真实消费者：纯展示改读 content；确实用于查询/幂等/状态/参数的字段继续保留。不能为了宽松而删掉代码正在依赖的硬控制值，也不能留旧字段作为另一份独立语义真源。

不合并 Todo/Task，不删除固化器，不重定位 M3，不引入新的实体/证据平台。本次改变的是内容组织与读取契约。

## 9. 实施和验收

先让存储、原文与单项材料读取可用，再切换 M5 默认输入；两个步骤作为同一设计闭包完成。同步更新原来强制“完整 snapshot 全文进入 prompt”的测试和文档，冻结内容可达性继续验证。

验收案例：

1. “review 这个”默认能同时看到准确原话和被指代链接。
2. 阅读某条消息不附带全项目、全参与者页或完整聊天。
3. 来源为邮件、会议事件、定时交办时使用同样分层，不要求伪造一个群。
4. Todo 后续修订不改变 Task 创建时的原始依据；历史实体内容与当前页明确区分。
5. 已有 Task 的结果可定位，失败 run 的实际副作用不丢；全局最新任务之外的相关工作仍能查到。
6. 材料可扩展任意语义字段，未知内容从采集到持久化到读取不丢失。
7. 加大三级背景/周边材料不会同步撑大初始输入；同时测初始输入、工具返回和整轮成本。

以此前 100 次运行作离线对照，不重放外部动作。此轮只有设计文档变更，未修改生产代码、数据、状态或服务。


## 10. 初始输入缩减估算（离线投影，非改造后实测）

使用同一批最近 100 个含完整 TASK_CONTEXT 的运行（2026-09-03 06:47 至 2026-09-05 03:53 UTC）。按 Unicode 字符统计：保留当前 Task 的全部语义、所有已引用消息原文、人工补充和必要身份元数据；实体全文/周边材料改为入口，去掉 current_world 和 previous_runs 全文；另为尚未生成的现场与背景简述预留每条 1,000–3,000 字符。此预留用于估算，不是实现中的截断阈值。

| 部分 | 现有中位数 | 投影后中位数 |
| --- | ---: | ---: |
| 初始完整 prompt | 42,925 | 19,072–21,072 |
| 业务上下文 | 26,774 | 2,916–4,916 |
| 固定指令等 | 16,174 | 保留原值 |

逐条配对计算，完整 prompt 降幅中位数约 51%–55%，业务上下文约 82%–89%。完整 prompt 的 P90 从 58,893 变为 19,841–21,841。

另算保守场景：额外保留所有不重复的冻结周边会话，只收缩世界背景、全局运行态和历史输出，仍预留 1,000 字符说明；完整 prompt 的配对降幅中位数约 49%，但大段会话的长尾仍然存在。

这不是任务质量回放，也没有验证哪些周边材料实际不可省。所有原文仍需可回读；现场简述的最终内容尚未生成。统计不等于 tokenizer token 数，不含 CLI 隐藏输入及后续工具返回；总 token/费用/耗时收益要在实施后的完整运行中测量。

## 11. 实施结果（2026-09-05）

已落地，当前协议见 [上下文设计](../design-context-pipeline.md)。Todo / Task 的业务定位不变。Todo 的两份大语义字段合并为 `content`，删除三个不再使用的平铺语义字段；Task 的来源和背景合并为 `source_payload`。原文以材料字典保存，M5、查询 CLI 共用渐进式投影。

在一次真实 SQLite 备份上验证了 3,008 条 Todo 和 1,338 条 Task，重复迁移通过。最近 100 轮历史 prompt 的重放测量（Unicode 字符、保持原静态指令不变）：完整输入中位数 43,116 → 17,443，业务上下文 26,988 → 1,239；逐轮完整输入缩减比例中位数 58.8%。历史数据尚无新模型生成的现场摘要，新增摘要和实际工具下钻需另计；这不是整轮 token、费用、时延或任务质量的测量。

复现：先用 SQLite backup 创建可丢弃的 `.context-replay.db` 副本，再设 `JARVIS_CONTEXT_REPLAY_DB` 运行 `go test ./internal/store -run ContextMigrationReplayCopy -v` 与 `go test ./internal/execute -run ReplayHistoricalPromptSizes -v`。迁移测试会修改指定副本，不能指向生产数据库。

服务已通过标准 `scripts/rebuild-server.sh` 重建并启动，健康检查 HTTP 200。真实 Task #1259 的默认工具返回约 2,300 字符，显式完整读取约 12,394 字符，两条原始触发材料完整可读；查询、修订号读取和历史 effects 读取通过。Go 全量测试、前端类型检查、17 项前端测试及前端构建通过。此次不额外触发会产生外部动作的 M5 任务，任务质量与整轮成本仍需在正常执行中观察。
