## 高频关注视角（按出现次数从高到低）

1. **量化与预期对照**：反复追问"数据是多少 / 预期多少 / 符合预期吗 / 目标咋算出来的 / 完成率为啥能完成 / 这个统计的什么 / 补效果数据"。看到结论先要支撑数据，看到数据先问目标基线和是否达预期。
2. **进展与时间线**：高频"进展？/ 上了么 / 什么时候 / 啥时候上 / 为啥这么久 / 能画个时间线吗"。对排期滞后、无明确 landing 时间、"预计本周"这类模糊表述特别敏感。
3. **产品必要性与优先级**：质疑"为啥要做这个 / 产品是不是先看看要干啥，感觉啥也没有就要上 MVP / 治理没有 OKR？/ 产品没有 KR？/ 这跟 Q4 有啥关系 / 常规的事情，Q4 增量表达清晰一些"。要求区分常规存量与本期增量。
4. **逻辑、归因与颗粒度**：质疑"这个直接关系怎么论证 / 怎么归因的 / 这个逻辑不太对 / 切的逻辑也有问题 / 颗粒度太粗了 / 话题应该是具体的事情，不是聚合大类 / 聚类是动态分组不是固定树结构"。
5. **边界、异常与存量/增量**：追问反向和异常路径——"准出逻辑是啥 / 退出公会失去开播权限吗 / 存量也是 opt-out 吧 / 拒绝后则？/ 倒扣咋考虑，不符合预期 then？/ 预发不还是发，发了不展示"。
6. **跨团队与职责分工**：关注"讲一下职责分工 / 不止产品还有策略团队 / 这应该算跨线需求，为什么不 involve / 这个渠道是不是应该产品化"。留意是否漏了相关方与责任归属。
7. **能力复用与平台化**：倾向把单点能力抽象成平台资产——"这个 agent 能应用在其他场景么（Rena/Bax）/ 是不是应该产品化 / 感觉要做一个 skill 广场"。
8. **调研与具象证据**：要求"举点例子 / 可以模拟一下 / agent 搓一个试一下 / 这个需要基于主播调研 / 调研录屏发我"。反对空泛描述，要 demo、样例、用户调研支撑。
9. **表达聚焦（尤其汇报/OKR 型材料）**：强烈反对啰嗦——"太碎了，总结 / 不要写废话 / 这是 OKR 总结？/ 重写 / 看下前面定的目标是啥"。要结论化、对齐既定目标。

## 对 PRD Review 的启示

评审 PRD 时应主动前置回答她最可能追问的点：目标基线与预期值、当前进展与上线时间、为什么做及与季度目标/KR 的关系、分类与归因逻辑是否自洽、准入准出与存量/增量/异常兜底、涉及哪些团队与是否漏 involve、能力能否复用或产品化、是否有调研/样例支撑。缺失这些即视为待澄清项。
