# Jarvis 世界模型与维护逻辑 Slides 方案

## 核心命题

世界模型不是一堆等待检索的记忆，而是 Jarvis 根据持续到来的证据，反复编译出的“当前工作世界”。

## 讲述范围

- 世界模型本身：实体、引用关系、当前认知、事实证据、认知版本与行动状态。
- 维护逻辑：Message / TodoEvent / TaskEvent 如何进入 FactEngine，维护 Agent 如何读、比较、判断和写回。
- 消费方式：冻结上下文、当前世界和按需下钻如何共同支持下一轮判断。

不展开完整产品场景、通用 RAG 综述、M2/M3/M5 全流水线或远期 Goal/Supervisor 设计。

## 计划页序

1. Jarvis 如何建立并维护自己的世界模型
2. 为什么普通 RAG 无法维护持续变化的工作世界
3. 世界模型的完整定义
4. 两个主体：长期实体世界与实时行动状态
5. 六类长期实体
6. 一个具体的 Jarvis 世界实例
7. 关系即实体页中的可验证引用
8. Summary / Fact / PageRevision
9. Todo → Task → ExecutionRun
10. 维护材料从哪里来
11. 世界模型编译循环
12. NOTHING / 新事实 / 认知前进 / 推翻旧认知
13. 游标、完整证据、CAS 与读回验证
14. FactEngine 主维护，M5 / Proactive 辅助维护
15. 世界模型如何进入下一次判断
16. 不是检索记忆，而是持续编译现实

## 最终视觉方向

已选择 Engineering Whiteboard Explainer：

- 真白工程画布 + 淡蓝网格，像一场可检查的技术白板讲解。
- 蓝 / 绿 / 橙 / 紫分别编码系统路径、当前认知、事实证据与认知版本；红色只表示风险。
- 右侧页码轮、逐 beat 揭示、路径绘制与局部卡片交互共同支持现场讲述。
- 每页只承载一个主判断，底部 takeaway lane 固化结论，代码位置以小标签作为证据。

## 交付物

- React + TypeScript + Vite 互动 HTML，共 16 个稳定场景。
- 16 页 PDF，每页固定 16:9，取各场景最终 beat。
- Playwright 跨浏览器、交互、路由、排版边界与视觉回归测试。
