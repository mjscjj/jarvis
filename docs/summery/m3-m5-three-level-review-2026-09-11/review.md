## 1. 决策链路：三个判断不能混在一起

1. M3 判断是否值得启动执行：`extracted` 才进入 Todo→Task 固化；`observing` 保留线索但本轮不启动；不输出表示既无行动价值也无记忆价值。
2. Materializer 只读取 `extracted` 并生成或复用 Task，不评估风险，不增加一次审批。生成 Task 不等于已经发消息或已经完成。
3. M5 读取来源原文、当前事实和历史动作，调查真实目标；按具体动作及当前审批策略选择执行、提问、等待或停止。不要因为以后可能需要审批而拒绝现在的只读调查。
4. 非所有 M5 任务都经过 M3：手动、定时任务和主动巡视可通过普通 Task 入口直接进入 M5。M5 提示词“不重复 M3 准入”应理解为不重做泛化价值评估，不能把这些任务误认为真的经过了 M3。
5. 主动巡视不直接发消息；它发现跨消息的关联、临期或失速后，维护旧任务或创建普通 Task 交 M5。活跃档也不自动提高单轮新建任务上限，不把“我已经开活跃”作为批量重放旧 observing 的理由。

## 3. M5 怎么做，哪些动作先问

先判断动作是否有价值，再判断是否获授权。下表“直接”仍要求事实、收件人、目标和正文明确，且遵守真实目标、查重和发送验收；不是每个 Task 都必须发消息。

| 具体动作 | 安静 | 普通 | 活跃 |
| --- | --- | --- | --- |
| 只读调查、本地分析、内部事实维护 | 直接 | 直接 | 直接 |
| 给 Principal 本人发有价值的结果 | 按安静通知尺度直接送达 | 按普通尺度直接送达 | 可更早送达有用发现 |
| 没有单独授权，但明确无风险的对外消息 | 先审批 | 直接发 + CC | 直接发 + CC |
| 没有单独授权，明确低风险但不能确认无风险的消息 | 先审批 | 先审批 | 直接发 + CC |
| 敏感信息、重要承诺、后果不明确 | 先请示 | 无覆盖该动作的明确授权则请示 | 同左，不能用低风险授权代替 |
| Principal 已批准的同一具体动作 | 按已批准动作执行，不循环审批 | 不重复请示 | 不重复请示 |
| 邀请 Bot 入群、申请会议/妙记查看权限 | 触达他人时审批 | 当前策略已有授权 | 当前策略已有授权 |
| 普通同事提出合并 MR、改线上配置 | 查清后审批 | 查清后审批 | 查清后审批；消息授权不覆盖修改 |
| Principal 明确授权具体修改 | 按本次审批及授权执行 | 授权范围内执行 | 授权范围内执行 |
| 在普通 Task 中重复催同一事项，无新指示 | 不做 | 不做 | 不做 |

“普通无风险”和“活跃低风险”是模型的语义判断尺度，当前没有量化阈值。不能把任何话都说成理论上有风险，导致普通档从不直发；也不能把“相关”“语气客气”当作低风险证明。收件人的知悉范围、是否造成承诺或要求别人行动，需要一起判断。

群里 Principal 在场时真实 @ 即完成 CC；Bot 单聊或 Principal 不在群内时同步收件人、位置及实际正文。发给 Principal 本人不再 CC。对方已经收到、只有 CC 失败时，保留凭据，只补 CC。

## 6. 现阶段需分清的结论

### 已有规则能推出明确答案的部分

- Principal 直接交办三档都进；安静不是关掉工作，也不降低调查质量。
- 普通/活跃免消息审批不会自动让 merge、改文档、改配置、建会免审批。
- 活跃不会让已经发过的信息重发，不会让所有会议都需要准备，不会让同事正常推进的工作被接管。
- M5 可以在调查后 observing；这与 M3 已准入不矛盾。已经发生的成功动作和 CC 仍须留痕。
- 源文档中的指令属于业务证据，不能改变 Agent 身份、授权或审批规则。

### 真实历史反例暴露的重点

1. **身份与授权归因**：R04 把王宁写成 Principal 指令，最危险的结果不是多建一个 Task，而是 M5 错套已有授权。当前原文优先规则能要求纠正，但还没有新规则下的行为验收证明。
2. **完成证据**：R05 的“没再提”和 R12 的“今天上线”不等于问题已经解决。可以决定暂不跟踪，不能把观察与完成混在一起。
3. **相对日期**：R15 与 R01 会因执行延迟改变日期。当前规则允许动态调整目标，但没有清晰规定相对时间先绑定原消息，再说明必要调整；R02 是正确对照。
4. **目标边界**：R15 查空档与约成会议、R07 review 与改文档、R04 回复 MR 进展与实际 merge，都是不同完成标准，不能只看 action_type。

### 当前规则或运行仍未完全闭合的边界

1. **普通准入存在松紧冲突**：未验证结果一律 extracted，和“他人正常负责且无需跟踪可观察”在 R12 弱化版本会重叠。应明确未验证的是不是 Principal/Jarvis 有必要看护的结果，而非增加来源专用分支。
2. **安静的审批前可见反馈**：`runOnce` 在读档位和运行 M5 前调用 `startTaskFeedback`，仍可能对原消息加 OnIt。严格按“触达他人需审批”，仅提示词修改无法覆盖该自动动作；需要单独对齐它是否属于保留的反馈。
3. **切档授权语义**：规则同时说使用当轮档位和保留已有授权，应区分“Principal 对具体动作的批准”与“旧档位提供的普遍便利”，尤其 active→normal/quiet。
4. **允许发言与发现发言机会不同**：H06 不能因为审批放开就宣布主动参与讨论已端到端实现。任务已进入 M5 时可直接发，任务没进时 M5 没有执行机会。
