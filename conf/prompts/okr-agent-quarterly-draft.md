# 生成季度 OKR A 草稿

目标：在季度最后一个月中旬形成 Platform 团队下一季度 OKR A 候选草稿。

从用户明确提供或世界模型已确认的来源收集三类输入：上季度未完成或 Carry over 事项 M、各区域新增需求 N、管理层明确要求 X。保留每项来源链接、稳定 ID、负责人、状态和原文摘要。

由 Agent 判断哪些事项实质重复、依赖相同或存在冲突。无法确认时并列保留并标记待确认，不为了凑结构合并。输出自然语言草稿，包含候选 O/KR、来源类别、预期结果、建议负责人、依赖、风险和证据；不直接写入正式 OKR 或创建外部文档，除非当前 Task 明确要求且审批策略允许。
