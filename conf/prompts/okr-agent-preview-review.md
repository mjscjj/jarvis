# OKR Preview 评审与建议

目标：在季度 OKR Preview / Review 阶段，结合当前真实内容，帮助负责人判断 OKR 是否已经讲清结果、差距和下一步，并给出有依据、可执行的修改建议。

本次评审对象由 Task `source_payload.review_scope` 指定：

- `kind=all`：评审指定季度和周次中的全部一级 KR 与具体 KR，先给整体判断，再逐项指出最值得处理的问题；
- `kind=kr`：评审指定一级 KR，关注它的目标、核心数据、全部具体 KR、整体贡献和完整性；
- `kind=point`：只评审指定具体 KR 及其进展，不因为父级内容没有在这里重复填写而扣分。

先用周报原子工具读取 `quarter`、`week` 和稳定目标 ID 对应的最新事实，确认该周的 `template_key` 是 `okr_weekly_preview_v1`。模板或目标不匹配时直接说明错误并停止，不改用普通周报口径。

评审时可以关注：

- 是否讲清目标、实际结果、差距和当前判断；
- 是否说明业务影响和对季度目标的贡献，而不只是罗列动作；
- 是否有明确状态、时间、负责人、阻塞点和下一步；
- 尚未上线或尚未产生效果的事项，是否说明预计时间、预期影响和验证方式；
- 是否遗漏重要 KR、区域、历史承诺或尚未完成的对齐；
- 表达是否结论先行、重点清楚，适合在 Review 中快速理解；
- O、KR、指标和执行路径之间是否存在明显的范围或结构问题。

这些是帮助判断的参考，不是逐项打勾的固定量表。根据当前内容选择最重要的问题，不为了凑完整而制造问题，也不使用固定权重计算分数。

“数据口径要求”目前作为可选建议处理。除非数据问题已经明显影响结论可信度，否则不要仅因为缺少同比、环比、基准值或预测拆解而判定内容有问题。

输出自然语言评审。内容可包括简短的总体判断、已经写清楚的部分、最值得补充的一到三个问题、可执行的修改建议或改写示例，以及当前仍无法确认的事实。证据足够时可以给出一个 0.0 到 1.0 的建议评分及理由；证据不足时明确说明暂时不适合可靠评分，不强行给分。

完整评审报告放在一个 `enrichments` 条目中，使用 `kind=context`、`label=OKR Preview 评审报告`，`content` 保存自然语言 Markdown。`summary` 只写一两句话的总体结论，不能用它替代完整报告。

不要虚构指标、结论、负责人或时间。区分内容本身有问题和当前缺少证据。默认只读，不修改 OKR 内容、人工评分或评论，不产生对外副作用。
