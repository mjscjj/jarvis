# 生成双周会 Report C

目标：合并最近两个有效周次的 Report A / WCU 周报事实，按 Q3 双周会 7 个 Key Focus Area 组织成可直接用于双周会的 Report C 材料草稿。

## 数据范围

- 默认读取当前季度最近两个有效周次；页面或 Task 明确指定季度、周次时以指定范围为准。
- 分别读取两个周次的周报事实，不得把当前周内容复制两次冒充双周数据。
- 只读取 KR、策略具体 KR、产品具体 KR 的 `Progress review` / 周进展正文及必要的核心指标值；不读取“已完成”列、`Not start` 条目、O/KR 定义行本身、`策略具体KR` / `产品具体KR` 标题字样。
- 原始证据不足时保留“待确认”，不得按标题相似度强行归类。

## 生成规则

1. 先按 KFA 映射收集两周事实，再清洗、去重、压缩，不调用固定报告生成器替代判断。
2. 输出 7 个 KFA，标题与 Q3 双周会表头一致；每个 KFA 下只填“Key Progress”需要的内容。
3. H1 标题下写注脚：`> 自动映射自 Weekly Catch Up - X.XX(26Y Q3 OKR 进展)`；若两个周次来源标题不同，写清两个来源。
4. 每个子项尽量用 1 句结论化表达：`做了什么 + 关键数据/范围 + 里程碑时间`。
5. 原文有“公会侧 / 区域侧 / AMS 侧”等分支时，保留同级子标题分区。
6. KFA3 工具固定按 KR3→KR2→KR1 输出，并用 `;` 串联，不写 `KR3 xxx:` 这类编号前缀。
7. KFA2 教育课程固定按“平台课；公会精品课”组织。
8. KFA5 Rena 先一句话汇总，再分别列 Reach、Match、流量诊断、通用内容理解 Agent。
9. KR 明确区分策略/产品时，默认输出“策略进展 + 产品进展”双轨；某轨无实质更新时合并为单条。
10. 每个 KFA Key Progress 控制在 200 字以内；公会运营相关 KFA 可以略超，但仍应优先压缩。

## 清洗铁规

- 删除空单元格、“本周无更新”、“无进展”、“待补充”、“待启动”、“-”、“无”等占位内容；KFA 全空时该 KFA Key Progress 留空，不写占位句。
- 删除 `(In progress)`、`(Done)`、`(Not start)`、`【进行中】`、`【未开始】` 等状态前缀。
- 删除“详评 / 对齐中 / 推进中 / 调研中 / 评估中 / 已发起”这类没有结论、数据或下一步时间的单独过程句；含“预计 X 月上线 / X.XX 上线”的里程碑必须保留。
- 百分比、公会数、主播数、区域数、区域名、时间节点、营收、曝光等关键数据原样保留；能成对表达时保留指标名、数值、变化量和对比基线。
- 里程碑优先写成“子事项 + 状态动词 + 区域范围 + 具体日期”；原文只有月中、月底、Q3 内等颗粒度时才保留模糊时间。
- 保留可见的 `<cite>`、`<chat_card>`、`<grid>`、`<column>` 等富媒体或引用结构，不转成“详见文档”。
- 不写交叉引用式表述，例如“同某模块进展”；同一事实在多个来源重复出现时只保留一次。
- 新公会孵化必须覆盖新手村有效渗透率 vs 基线、平台课到课率/区域 pp 增量、区域开区/上线进度；确有缺项时写“暂无数据”。

## 判断与自检

on track / not on track 是结合 KR 目标、计划节点、两周变化、剩余时间和明确风险作出的语义判断。每项判断给出简短依据；证据不足时写“待确认”，不按固定状态字符串代替判断。

生成后自检：

- 7 个 KFA 齐全，标题与 Q3 表头一致。
- 各 KFA 内映射要求的子项齐全，尤其 KFA1 三项、KFA2 引入三项 + 孵化新手村 / 平台课 / 精品课、KFA5 Bax for AM / for Backstage + Rena 拆 Agent。
- 全文无“本周无更新 / 无进展 / 待补充”及“详评中 / 对齐中 / 调研中”单独成句。
- 数据有绝对值和变化率，里程碑尽量精确到日。
- 输出中无 KR 编号前缀、无已完成列条目、无 Not start、无 O/KR 定义行、无重复、无交叉引用。
- 富媒体和引用结构已原样透传。

## 产出边界

输出模板化 Markdown、两周范围、来源和待确认项。默认固定落点为本次 Task 结果，只生成内部会议草稿，不创建外部文档、不发送消息；只有用户在当前入口明确要求时，才使用周报原子工具创建飞书文档或执行其它外部副作用，并在写后回读确认。
