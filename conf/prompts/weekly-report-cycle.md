# 周报周期流程

这份配置定义周报模块的业务节奏。具体工具命令和外部系统边界由对应 Skill 负责；调度、幂等、审批、身份和真实发送由运行时代码保证。

## 1. 开放填写

- 读取当前季度、周次和上一周版本。
- 周期未创建时，只生成本周填写范围，不覆盖上一周历史。
- 把已确认的 Meego 或消息变化作为候选信息展示，不在没有直接证据时替负责人填写结论。
- 周报页面进入可填写状态后，记录截止时间和会议时间。

## 2. 首次催填

- 只处理当前周应填写且尚未完成的负责人。
- 按负责人聚合缺失 KR，一人一条消息，不按 KR 重复发送。
- 先生成不可变预览批次；没有真实 open_id 的负责人进入人工处理，不猜测身份。
- 只有审批策略允许时才真实发送，所有发送保存逐人回执。

## 3. 进展收集

- 人工填写是正式周报真源。
- Agent 可从 Meego、消息和文档提取候选变化，但必须保留来源、时间和匹配依据。
- 自动证据与已有内容冲突时标记需要复核，不覆盖人工更新。
- 重复读取同一版本证据不得重复新增进展。

## 4. 截止检查

- 截止前再次计算缺失项，只提醒仍未完成的人。
- 已完成、未分配、无真实身份或明确跳过的人不发送。
- 部分发送失败保留 partial，并列出成功、失败、跳过对象。

## 5. 冻结会议版本

- 会议材料必须基于一个明确的周报版本和数据截止时间。
- 冻结后新增修改进入下一版本，不能静默改变会议已使用的内容。
- 风险、核心数据变化、已完成事项和缺失内容必须可追溯到 KR 和来源。

## 6. 生成与审阅材料

- 先生成内部草稿，不创建外部文档、不发送消息。
- 草稿必须列出本周变化、成果、风险、需要决策、下一步和数据缺口。
- 人工确认后的草稿保存版本；临时投影不能直接发布。

## 7. 发布与关闭

- 发布前必须有已保存草稿、明确目标和必要审批。
- 发布后记录文档 URL、发送目标、成功回执和失败项。
- 周期关闭时保留周报版本、评论、来源、动作记录和材料版本，并把确认后的结果向 OKR 汇总。

## 完成标准

- 页面能看到本周状态、截止时间、缺失人员、最近催填、会议版本和发布结果。
- 调度成功、Task 执行成功、外部送达成功分别记录，不能互相冒充。
- 失败、需人工和部分成功必须保留真实状态和下一步。
