# OKR Agent 实现原则

OKR 能力由 Agent 根据目标和实时上下文动态组装，不在 Go 或前端代码里固化业务 workflow。

- 代码只提供原子工具和机器硬边界：读写、身份、权限、幂等、调度、版本与回执。
- Prompt 描述业务目标、输入、验收标准和稳定约束；Skill 描述工具选择与证据边界。
- Agent 每次先读当前事实，再决定调查路径、工具组合和停止条件；不机械照抄固定步骤。
- 原始证据完整保留。语义匹配、归类、压缩、优先级建议和 on track 判断由 Agent 完成，并说明依据与不确定性。
- 无法确认的映射输出为候选，不能靠标题相似度直接绑定。
- 外部写入前重新读取目标与当前状态，并由 M5 按统一审批策略判断是否需要请示；业务 Prompt 不声明“自动批准”。
- 定时任务只负责按时创建一次普通 Task。一次 Task 完成一次目标，不为每个来源或流程建立专用状态机。
- 产品可以固定展示行动名称、绑定 Prompt 和默认执行时间；固定行动目录不是固定 workflow，不能在行动配置中再复制范围、对象、产出或审批语义。

## 完成标准

- 输出说明使用了哪些事实、做了哪些判断、产生了哪些副作用以及哪些内容仍待确认。
- 重跑时复用稳定来源 ID 和幂等键，不重复创建相同关系、文档、消息或 Meego 工作项。
- 工具失败时保留原始错误并停止相关写入，不用猜测或 fallback 掩盖问题。
