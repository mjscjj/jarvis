# M3 抽取专属工作规则

## 线索频道（chat_mode=clue）

`chat_mode=clue` 的会话不是飞书聊天，是采集者投递进来的**外部事实**：一条线索只陈述「发生了什么」，采集者不做任何判断，也不替你去抓后续材料。**判断它意味着什么、还需要补什么，是你的活。** 看到这类线索，默认先动手查，再决定要不要产出 Todo。

## source=feishu_meeting：一场会开完了

线索只会告诉你会议主题、meeting_id、起止时间、主持人、参会人和会议链接。妙记有没有、录没录、生成好没有，线索里都没有——**你自己去查**。

拿到一条会议线索后：

1. 用 `lark-cli vc +detail --meeting-ids <meeting_id> --as user` 看这场会有没有 `minute_token`。
2. 有 token 就用 `lark-cli minutes +detail --minute-tokens <token> --as user` 往下取，按需要加 `--summary` `--chapter` `--todo` `--transcript`。
3. 根据返回自己判断当前是哪种情况，不要套固定结论：
   - **压根没开录制**：查不到 minute_token，也没有任何妙记痕迹。这场会没有可追的会后产物，除非参会人和主题本身说明有值得跟进的事，否则不必硬造 Todo。
   - **妙记还在生成**：接口返回 `status=processing` 或类似「处理中」的状态。这是暂时的，会好的。
   - **没有查看权限**：接口明确报权限不足。
   - **妙记可读**：能正常取到内容。

只要**有 minute_token**（上面后三种情况都是），就产出一条 `summary_post`，并把已知阻塞（还在生成 / 没权限）写进 description 和 semantics。拿不到内容**不是**不产出的理由——申请权限、挂起等待、到期重探都是 M5 的活，你只要把「拿到什么才算完」和「现在卡在哪」交代清楚。

`desired_outcome` **必须锚定妙记产物**，统一写成这个意思：

> 基于这场会的飞书妙记，产出一份含会议结论、达成的决议、待办及其负责人、待确认事项的完整纪要，并送达（发到对应群或发给我）。

不要写成「拿到会议结论和落到我头上的待办」这类宽泛说法——群日报、周报、别人发的总结都能满足它，M5 会据此判定目标已达成而跳过整理。也不要把 `desired_outcome` 写成「申请妙记权限」，那只是中间步骤。

妙记可读时，除了这条 `summary_post`，再按平时的标准抽取会上明确交办给我的、我自己承诺的、明显在等我推进的独立事项。

上面四种情况的边界靠你看接口返回自己判断，不要凭会议主题猜。

一场会议只对应一条会后整理线索：`target` 稳定携带会议主题和 meeting_id，便于跨轮次去重。会中另外交办的独立事项，正常拆成各自的线索。
