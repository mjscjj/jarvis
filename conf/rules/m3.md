# M3 抽取专属工作规则

## 线索频道（chat_mode=clue）

`chat_mode=clue` 的会话不是飞书聊天，是采集者投递进来的**外部事实**：一条线索只陈述「发生了什么」，采集者不做任何判断。你要判断它意味着什么、该不该产出 Todo、产出哪种。**但抽取阶段要轻**：能从线索本身和已带背景判断的就直接判断，不要在这一步做重活或长链路的联网调查——真正的调查、补全和闭环交给 M5。每类 source 的具体处理见下。

## source=feishu_meeting：一场会开完了

**你只负责落，不负责查。** 收到一条会议线索，就机械地产出**一条 `status=extracted` 的 `summary_post` Todo**——一场会一条，不去 `vc +detail`、不取妙记、不判断有没有录制 / 妙记生成好没有 / 有没有权限。那些查妙记、申请权限、等对方同意、到期重探、拿到内容后整理并发送，全是 M5 拿到 Task 之后的活；M5 有工具也有可恢复等待，能自己把这条闭环走完。你在这一步多查一次，就是把 M5 的判断抢过来、还会把抽取跑到超时。

线索里已带会议主题、meeting_id、起止时间、主持人、参会人和会议链接——把这些原样放进 payload 即可，缺什么就缺什么，不要为补齐去调任何接口。

payload 中的最终结果**必须锚定妙记产物**，统一写成这个意思：

> 基于这场会的飞书妙记，产出一份含会议结论、达成的决议、待办及其负责人、待确认事项的完整纪要，并送达（发到对应群或发给我）。

不要写成「拿到会议结论和落到我头上的待办」这类宽泛说法——群日报、周报、别人发的总结都能满足它，M5 会据此判定目标已达成而跳过整理。也不要把最终结果写成「申请妙记权限」，那只是 M5 的中间步骤。

一场会议只对应一条会后整理线索：`target` 稳定携带会议主题和 meeting_id，便于跨轮次去重。会中另外交办的独立事项由 M5 在整理妙记时自然识别，不需要你在这一步去拆。
