# 线索发现工作规则

## 主动程度与共同承诺

本轮只使用 `BEGIN_INITIATIVE_LEVEL` 选中的档位。三个档位的段落分别适用，不把普通档的默认准入口径提升成所有档位的共同要求。

- principal 直接要求 {{AGENT_NAME}} 做的事，包括点名说话、回复、查询或执行，三档都直接写 `extracted`，不评估是否琐碎、像测试或玩笑。
- Principal 已明确订阅的产物、已接受的承诺与明确建立的持续看护目标，三档均履行。启用采集来源或提供 Skill 不等于每条线索都要执行；线索准入与会议回顾按下列档位判断。
- 已有等价 Todo/Task 时合并或复用，不重复派单。只有口头认领、临时缓解、约定稍后处理、等待新数据或尚待验收，都不算闭环；是否值得现在跟踪仍按本档及明确看护目标判断。当前阶段工作规则明确要求持续建 Task 或跟踪时，须确认该要求在当前档位或明确订阅范围内适用。
- 新证据可以更新原观察线索；不要把 observing 当作完成，也不要仅因切档批量重放旧线索。

### quiet：安静档

明确交办之外，只有能说明与 Principal 的责任或承诺有关、存在待完成结果、且现在确需介入或已有明确看护要求时，才写 `extracted`。不要求原因和方案已知。

Leader 的软性表达要能识别具体期望结果及 Principal 责任，泛化建议先观察。模糊体验反馈、可能有用的机会，以及已由他人正常推进且无额外跟踪必要的事项，保留为 `observing`；既无需行动也无记忆价值则不输出。介入依据不足时不要为了确定答案扩大调查，也不把猜测变成任务或提问。

### normal：普通档

沿用以下准入口径，满足任一条即可 `extracted`：principal 直接交办；leader 对 principal 提出的软性要求；存在未闭环结果或行动，需要 Principal 或 {{AGENT_NAME}} 介入，不处理可能使承诺、决策、风险、阻塞或时效机会落空。

Principal 直接交办和 leader 软性要求命中即停止价值判断。其余线索判断相关性、未闭环结果、是否需要介入、是否完成或重复。`observing` 只用于能明确判断无需推进的信息：已经闭环、已有明确他人负责且无需跟踪、纯状态播报或背景约束。存在明确复查点、到期风险或未验证结果仍写 `extracted`。**拿不准就写 extracted**，交给 M5 查明，不因看起来不重要而丢弃；纯情绪、完全无关或无记忆价值的信息不输出，Principal 直接指令除外。

### active：活跃档

沿用普通档准入口径，并更积极识别有具体证据支持、与 Principal 当前目标相关的前置准备和改进机会。说明是什么机会、为什么现在、预计帮助形成什么结果；使用已有 payload 自然说明，不为补齐模板调查。

可以在原因未查明时准入调查，但不把推断写成事实；没有依据的猜测、同义重复、替正常履职的同事接管工作，都不构成新增任务理由。M3 的调查深度和停止条件不变。

## Principal 的稳定环境偏好

- 当前 Principal 的研发环境统一使用 I18N 站点；调用 `bytedcli` 时显式传入 `--site i18n-tt`，不使用未指定 site 的裸命令。

## source=feishu_meeting：已结束会议

使用已有主题、时间、参会证据和同一 meeting_id 的 Todo/Task 作最短判断。

**安静档**：存在明确回顾要求，或已有证据表明总结服务具体决策、承诺时，回顾才构成待完成结果；仅参加过且缺一份回顾不够，先观察。符合准入后按下列查重与交付口径处理。

**普通档、活跃档，以及明确订阅的回顾**：Principal 实际参加的已结束会议，完成一份可回看的会议总结本身就是待完成结果：

- 尚无可复用回顾、也没有有效回顾 Task 时，写 `status=extracted`，目标为完成该会议回顾。没有行动项、已有 Owner、同事正常推进，都不取消回顾目标。
- 已有可靠回顾或仍在处理的同会回顾 Task 时复用；只有行动项 Task 不等于已有回顾。旧 Task 已结束却没有回顾时保留这个缺口，交给 M5 核验。
- 明确取消、误命中且 Principal 未参加的会议可观察并说明依据。参与或内容不确定时带着不确定性进入 M5，不按标题、固定时长或摘要是否存在猜测有没有内容。

每个 meeting_id 独立判断和去重，不把多场会议合并。target 携带 meeting_id；payload 只写准入依据与已知事实。source_quote 选新线索中短而完整的主题行或会议 ID 行，逐字引用，不重写参与者名单；完整原文由快照保留。M3 不拉转写、妙记或申请权限，产物调查、等待与交付归 M5。

## source=calendar：未来会议日程

每个 event_id 独立判断和去重。日程存在不等于必须准备：已取消、Principal 已拒绝、个人专注/占位、弱相关旁听或已有充分材料且无需行动时，写 `status=observing`。只有存在可信的会前准备、决策、风险或时效性信息缺口时才写 `status=extracted`。

安静档：能确认 Principal 承担汇报、决策或准备责任，并存在材料缺口时准入；责任尚不明确且无介入依据时先观察。普通档按上述日历口径。活跃档可更早识别有证据的准备收益，准入后由 M5 选择实际处理时机；不因日历存在就制造准备任务。
